## 本轮计划与验收

1. 并行审查协议/核心、runtime/持久化、测试/证据，先复现再修复重要问题。
2. 核心：终点不占转发队列；visited 邻居在完整已验证路径上快速排除，避免空转重新验签；所有公共入口保持时钟高水位；自动过期通知必须有界且不丢失。
3. Runtime：转发撤销/连接关闭释放对应 offer；使用同一有效时间检查 TX 到期；核查持久化错误及重启失败状态。
4. 测试：保留无关异步事件、实际强杀重启后的重复输入、监听启动后的隔离负例、明确断连重连的分区恢复。
5. 性能：旧二进制与新二进制使用同一 loopback 实验负载、每来源不超过 16/min；记录空闲与有缓存时的 CPU tick、RSS/PSS 和端到端延迟。结果仅为本机 TCP，不能外推手机/无线。
6. 仅对变更范围运行必要验证，保存原证据并新增本轮证据，更新中英双语 PR；保留剩余边界。

实现和实测结果在本轮完成后追加，不能将计划当作测试通过记录。

## 审查与修复结果

| 问题 | 修复与验证 |
| --- | --- |
| 跳数耗尽的有效收件仍挤占 forward queue，阻止本地发送 | 终点只进入验证/去重/展示；回归 `exhausted_received_routes_do_not_block_forward_queue_or_local_messages` 先复现 queue_full，再通过 |
| 对路径内邻居每轮重新验证整条 hop 链，随后才拒绝转发 | 在私有的已验证 pending 上先排除 origin/route.to；入口验证和真正 append 的验证保持不变；同一原始/新二进制负载对照见下 |
| 拒绝过期输入、过期 next_for、失败 originate 没有推进时间下界，可被随后的本地时钟回退复活 | 所有相关入口观察可信主机时间；TX 前也新采样、推进下界；完整 TX 队列遇到阻塞跨过期限后不能再发，取消后回退也不能重 offer |
| admit/restore_seen 内部清理吞掉到期通知 | 最多 Limits.pending 个延迟通知；满时保留后续到期 pending 并背压；tick 返回全部待通知 ID。容量 1 的重复过期测试确认不驱逐/不无限增长 |
| relay-off 撤销未发送帧，Core 仍认为已 offer | 有界 take_cancelled + pending_ids，取消和任意连接关闭释放特定消息/邻居 offer，保留其他邻居及最多三次准备上限；部分发送仍关链接维护 framing |
| 已判死的首选重复连接可反过来淘汰健康连接 | 去重跳过 dead i，i 被淘汰后停止比较；真实 Link fixture 先复现 dead={0,1}，修复后仅保留 dead={1} |
| checkpoint 的非 IO 错误被当作邻居错误，节点继续接受/转发 | 从 peer 错误处理分支分离成功消息的持久化；所有失败都在展示/转发前退出。symlink 测试先复现继续运行，再验证拒绝覆盖 fixture、退出且无展示 |
| 本地 send 负数/float/bool/null 等 ttl/hops 悄悄采用默认预算 | 只有缺省使用默认，错误类型显式 budget_type；回归包含上述输入与合法整数 |
| 异步测试 wait 丢弃无关事件、重启测试未真正要求 replay、隔离检查早于监听 | 驱动保留事件、完整负例窗口及 fresh barrier；SIGKILL 重启后要求 failed_restart 与原 ID 的 duplicate；监听正对照成功后才接受 A/C ENETUNREACH/EHOSTUNREACH |
| 分区检查可能只测了 TCP 内核缓冲，跨代去重记录不全 | 先关闭 C 并等 B neighbor_down，再在链路 down 后重启 C，确认 B 持有新 ID，链路恢复才完成交付；统计所有 B/C 代际 |
| 诊断导出未约束结构化原始字段/类型，捕获输出可无界缓存 | 对当前 Java 事件使用 event/field/type/token 白名单，拒绝 bool schema、原始 MAC/SSID、未知字段/嵌套值；原始采集有行/总量/超时上限。假可执行文件回归，无真实设备 |
| 拓扑记录仅有二进制路径，source HEAD 被误当作任意 binary 的构建证明 | schema 2 记录实际 binary SHA/size、driver hash、源码 snapshot/dirty；声明工具不认证 binary/source 对应。新清单包括采集测试和 workflow/config 输入，拓扑拒绝运行中替换 binary |

上述审查由三个并行审阅任务与独立补丁复审协助完成。复审发现的 TX 新鲜时间遗漏也先写失败回归再修复。最终审查/回归不是正式第三方密码学认证，不能推导未测平台或无线结果。

## 同负载性能对照

原始与新二进制顺序运行**同一份** `mesh/tools/bench.py`，脚本 SHA-256 `1c69a14346027da1ddf243966a690078fe71e8280ee5ffc13ddf5722403164d6`。原始 release 复用上轮已保存、摘要匹配的产物，不重新构建旧版；新 release 编译器/配置仍为 Rust 1.88、strip/thin LTO，依赖图和签名字节未变。

每种负载三轮独立状态、每轮三个进程，位于仅启用 lo 的独立 user/net namespace。5/2048 bytes 用每方向 2 条 warmup + 12 条测量，共 28 条消息，每来源 14 条，低于 16/min；每轮两端各展示 14 条，B 展示 28 条，无拒绝/错误。邻接建成后计时，不含冷启动；这不是 throughput benchmark。

| 已建立 TCP / 保留消息后的静默负载 | 原始 / 新版累计 CPU tick（3轮） | 原始 / 新版累计 CPU 秒（约3×1.5s静默窗口） | 原始 / 新版延迟 ms |
| --- | --- | --- | --- |
| 无缓存消息对照 | 0 / 0 | 0.00 / 0.00 | 不适用 |
| 28条 5-byte 缓存消息 | 71 / 1 | **0.71 / 0.01** | 11.55 / 11.19 |
| 28条 2048-byte 缓存消息 | 70 / 1 | **0.70 / 0.01** | 10.98 / 10.89 |

CPU 为 A/B/C 三个主进程 `/proc` 前后差值之和，每进程 tick=10ms；读数 0 不表示真正零开销。每轮静默长度及原始 tick/PSS/RSS 都保留。延迟一栏是三个独立轮次中位数的中位数，每种 payload 共 72 个测量样本；差异较小，不给出尾延迟或确定提速比例。明显改善来自不再为空转的“来路邻居”重新验签，不是降低入口验证、消息数量或同步去重落盘要求。

二进制由 1,856,304 增至 **1,864,496 bytes**（+8192 bytes），新版 SHA-256 `187f6c673724d8928ef6dd12dfd799bc669043b075c5ece0eaa1c96df42fb154`。本轮不宣称内存缩减：各轮父进程 HWM、三进程 PSS 和 RSS 点样本有浮动，2048-byte 情况新版 PSS 并未更低。实际数据见 [baseline](../../mesh/evidence/review-2026-11-01-baseline.json) / [optimized](../../mesh/evidence/review-2026-11-01-optimized.json)。

本机仍为 Linux x86_64 / glibc2.41，cgroup 为 2 CPU 配额、8GiB；没有手机功耗、无线吞吐、长期压力成绩。1.5s 短窗口也不能代表包含每10s持久快照的长期待机成本。

## 补强后的隔离验收与资源记录

- [配置候选](../../mesh/evidence/review-2026-11-01-isolated.json) 与 [DNS-SD](../../mesh/evidence/review-2026-11-01-discovery.json) 都通过：先从 B 连接存活 A/C listener 得到 0；A↔C 都明确为 101 / ENETUNREACH，B kernel forwarding=0。
- 两种模式都验证双向签名路径、完整 TTL 的 relay-off 负例、实际断连/重新建连后的分区消息、B 重启后的原 ID 重放拒绝，以及跨 B/C 全部代际无重复展示。
- 新版两组隔离 TCP 的 12 条小消息中位延迟分别 9.65/9.93 ms；验收脚本时序已补强，不能把它直接与历史脚本的 11.12/11.42 比例比较作性能收益。
- 本轮 DNS-SD 点样本把 worker 计入进程树：每节点两个进程的 RSS 和为 **5068–5476 KiB**，PSS 和为 **1476–1867 KiB**（含 B 重启前后采样），没有丢失 PID。它是顺序 procfs 点采样，不是持续峰值；RSS 和重复计算共享页，PSS 适合辅助解释物理占用。96MiB 仍仅是 worker 地址空间配置限额。

完整本地验证为 **60 项**：36 Rust（3 CLI/runtime 单元 + 19 core + 14 framing/resource）、11 个真实 Mesh 进程案例、4 个异步驱动 fixture、9 个 capture/parser/限额案例；fmt/clippy 通过。两次隔离脚本额外断言不计入 60。Java 源码/依赖未变，复用原 Java/DEX 编译证据，未生成/提供 APK。

## 剩余边界与后续工作

真实无线仍为 **hardware validation pending**；无 native radio adapter/FFI/后台常驻/可靠 DTN/平台密钥库/其他平台构建或电量成绩。DNS-SD worker 的异常细节仍未导出到诊断（资源/重启节流有界，状态也不声称发现成功），后续需要更明确的可观测性。同步快照与短周期唤醒的长期成本需要另测；本轮没有削弱持久去重保证。

采集工具在 Linux/POSIX 控制机验证；每次运行的 token 不能宣称不可逆匿名。签名链仍只是逻辑预算，不能证明物理邻接、阻止串通隧道或 Sybil。当前研究、架构和这些已声明限制继续有效。
