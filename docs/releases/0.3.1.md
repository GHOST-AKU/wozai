# 我在 · NearbyIM 0.3.1

本次以正式 GitHub Release 发布 Android、Windows x64、Linux x64 客户端，包含 PR #12 已合并的文件／照片传输及修复。

## 下载与安装

- Android：`NearbyIM-0.3.1-android.apk`，Android 8.0 / API 26 及以上，versionCode 7。经过 R8 和资源裁剪，应用不可调试，沿用当前交付测试包的调试签名证书。
- Windows：`NearbyIM-0.3.1-windows-x64.zip`。解压后运行 `NearbyIM/NearbyIM.exe`，内置 Java；保留已有 `data` 目录，安装包不包含用户身份或聊天数据。
- Linux：`NearbyIM-0.3.1-linux-x64.tar.gz`，或 Debian/Ubuntu 的 `NearbyIM-0.3.1-linux-x64.deb`。内置 Java，数据位于 XDG 用户目录；需要图形桌面，蓝牙需要 BlueZ / D-Bus。
- 以 Release 中的 `SHA256SUMS.txt` 检查下载，`BUILD-MANIFEST.json` 记录源提交、资产大小、哈希及验证工作流。

## 本次改动

- 三端文件／照片传输，单文件最多 1 GiB，流式分块、签名验证及 SHA-256 完整性检查；完整保存后确认送达。
- 认可聊天后自动接收附件。照片显示缩略图，点击在应用内查看；桌面支持缩放，其他文件可另存为。
- 参考 WhatsApp 的圆角输入栏、附件选择和发送按钮，采用 Google Material 图标。
- 修复安卓同意聊天后因存储接口兼容导致失败，以及附件任务队列满时崩溃；统一清理导出文件名。
- 移除安卓图片元数据依赖，限制元数据读取；缓存桌面图标并限制缓存容量，降低重复绘制分配。

## 升级和验收范围

通信协议为 NIM3。双方都必须更新到支持 NIM3 的版本，旧公共 NIM2 预览版不能互通。握手及数据有签名，内容尚未端到端加密。

安卓证书 SHA-256：`47a10fd5a882ab26c9a11fcc61df3b41f7c41017746fc6840cfbe581ca52c1dd`。与当前交付测试包一致，versionCode 由 6 升到 7。原长期签名密钥缺失，旧公共包的保留数据升级没有完成验收（Issue #8）；不要为覆盖安装而卸载有聊天记录的旧应用。

三端构建和自动检查均须通过后才发布。安卓验证的是最终发布 APK 的同一字节，在 API 26 / 34 模拟器上执行原生检查；Windows / Linux 检查实际打包运行时、GUI、多种缩放和局域网通信。

自动检查不替代桌面蓝牙适配器与手机的真机互通验收（Issue #7）。Windows 有线网络发现仍按用户要求暂停处理（Issue #5）。空闲／仅连接的长时间内存增长尚未完成验收（Issue #9）；图标分配降低不表示整个程序的内存泄漏已解决。自动接收当前没有累计的对端存储配额；不支持解码的图片保留原文件并提供另存为。

## 发布维护

从已合并 main 调整共享版本及安卓单调递增的 versionCode，再提交到发布分支。创建指向该准确提交的 `v0.3.1` 草稿；本地用现有证书构建优化 APK 和对应测试 APK，上传应用、临时测试 APK 及输入清单。手动运行 Android workflow 的 `release-tag=v0.3.1`，验证这些确切字节。

运行 Windows workflow，选择 `include-linux=true` 和 `release-tag=v0.3.1`。三端通过后，桌面 staging job 校验 JAR 源提交及版本、Debian 版本和 Windows 无用户数据，再向同一个草稿上传安装包。普通工作流保持只读，只有上传／读取草稿的独立 job 具有仓库写权限。

核对哈希、签名和 CI 证据，删除临时测试 APK 与 Android 输入清单，再上传公开的校验清单、构建清单和发布说明。将版本提交同步 main，发布为非 prerelease 的 latest Release。不会上传签名私钥，也不会用 CI 临时生成证书替换当前用户安装证书。
