# 我在 / NearbyIM 0.3.3 — 发行说明 / Release notes

# 我在，现在也在 Apple 设备和终端里。

**0.3.3 最重要的变化，是多了两套全新客户端：面向 Mac、iPhone、iPad 的 Apple 原生客户端，以及面向 Windows、Linux 的独立 TUI / CLI 终端客户端。**

从手机到电脑，从图形界面到命令行，你可以用更适合自己的方式和附近的设备聊天、传文件。不用注册账号，也不用先把内容交给云端服务器。

下面介绍的是**相较 0.3.2，整个 0.3.3 开发周期带来的变化**，包括此前在预览版中陆续亮相的功能。

## 🍎 你好，Mac、iPhone 和 iPad

我们用 **Swift / SwiftUI 从头开发了 Apple 原生客户端**。它有自己的原生界面，也能通过局域网与 Android、Windows、Linux 交换加密消息和文件。

- **熟悉的 Apple 操作方式**：Mac 的侧栏、工具栏、菜单与设置窗口；iPhone 的导航；iPad 的分栏。字体、SF Symbols 图标、明暗主题和系统组件都遵循平台习惯。
- **文字之外，也能传文件和照片**：选择、多选、排队发送、接收确认、暂停与继续，以及系统预览、分享和接收目录选择。
- **聊天留在自己的设备上**：本地记录、草稿、送达状态，配合设备认可、安全码和二维码核验。
- **大屏可以按自己的习惯调整**：Mac / iPad 的原生分栏支持拖动与吸附，保留我们已经确定的默认布局。

Apple 端也接入了系统点对点发现与连接接口。不过，接口已接入不等于无路由器真机验收已经完成；它与 Android Wi-Fi Direct 也有不同的能力边界。当前 Apple 客户端仍按原生预览能力提供，具体范围见 [Apple 说明](https://github.com/GHOST-AKU/wozai/blob/main/docs/apple.md)。

## ⌨️ 终端里，也能好好聊天

**NearbyIM Terminal 是新开发的独立 Rust 客户端**，同时提供两种用法：

- **TUI：留在终端里的聊天界面。** 用键盘切换聊天、附近设备和文件，搜索会话、编辑多行消息、查看历史、保存草稿。布局会随终端宽度调整，窄窗口也能使用。
- **CLI：把聊天和文件收发接进工作流。** 用命令扫描设备、发文字和文件、管理传输与信任；通过 JSON 输出、退出码和 shell 补全，与本地脚本配合。

它不需要 Java、桌面 GUI 或 Android SDK，也能通过 NIM4 与图形客户端进行局域网通信。终端版使用独立身份和数据目录，LAN 监听默认关闭，首次设备认可与文件接收仍由用户决定。

这一轮还补齐了终端的五语文案、帮助、首次启动引导与命令行提示，重新整理了界面。无论你更喜欢打开一个窗口，还是敲下一条命令，都有对应的入口。

[看看 Terminal 怎么用](https://github.com/GHOST-AKU/wozai/blob/main/terminal/README.zh-CN.md)

## 💬 聊天，顺手一点

### 消息送到了，还是已经看过了？

原生客户端现在支持**文字已读回执**，并用单勾、双勾等状态图标区分消息进度；Apple 使用平台原生符号。

已读默认开启，也可以随时关闭。双方都开启，而且消息文字实际显示在前台聊天页后，才确认已读。已读标记使用 **`#66CCFF`**：浅色界面清爽显示，深色界面加一点柔和的光晕。Terminal 本版暂不支持已读回执。

### 写长一点，表达多一点

支持协商的客户端之间，单条文字上限提高到 **32 KiB（32768 UTF-8 字节）**；与旧版或尚未协商的客户端连接时，继续保持 **8192 字节**的兼容上限。

输入框不再常驻显示字节计数。我们也修正了草稿保存问题，让日常输入少一些打断。

### 表情更好找，语言更好换

Android 与桌面新增轻量的 **Unicode 表情选择器**：分类、搜索、最近使用和肤色变体都能直接找到，插入后还可以接着挑选。

界面支持**简体中文、繁體中文、English、日本語、한국어**。桌面手动切换语言后即时刷新，系统语言回退更清楚；README 也新增了日语、韩语入口。

## 🖥️ 大屏、Linux，还有连接与传输

这轮不只有新客户端，也收拾了不少使用中的细节：

- **平板与折叠屏**：修正按钮与矮宽窗口下的操作细节，加入分栏拖动的默认位置 / 中线双吸附，保留已确认的默认比例和调整范围。
- **Linux AppImage**：修复 Ubuntu 22.04 的运行时兼容问题，继续提供 AppImage、deb 和 tar.gz 三种包。
- **有线与 Wi-Fi 设备发现**：改进多网卡场景下的发现逻辑、地址选择与连接诊断，更方便排查电脑和手机为什么找不到彼此。
- **文件恢复与选路**：修正已完成任务的迟到状态处理、恢复快照更新和临时拒绝后的重试，并改进路径比较与切换成本判断。
- **传输诊断**：补充单次任务的阶段耗时、有效数据量与恢复口径，方便定位卡在哪一步；诊断摘要也不再直接暴露原始传输 ID。
- **相册文件名**：修正 Android 相册导出文件名的长度处理，覆盖多字节文字与 Emoji 的边界。

这些是具体的实现与兼容修正；无线性能、跨设备发现和断路恢复的真实表现，仍按对应 Issues 的设备与网络证据跟进。

## 🤖 也给自动化留了一个入口

新增 **官方 NearbyIM Agent Skill**，为通过 CLI 使用「我在」的自动化提供操作说明，覆盖命令调用、结构化结果和信任边界。它与新的终端客户端一起，让本地工作流有了更多接法。

## English — new clients, more ways to be nearby

**The biggest additions since 0.3.2 are two newly developed clients: native Apple apps for Mac, iPhone and iPad, and an independent Rust Terminal client offering both TUI and CLI.** This release brings together the work across the whole 0.3.3 cycle, including features introduced in earlier previews.

### Native Apple apps

Built from the ground up with Swift / SwiftUI, the Apple clients use platform-native navigation, sidebars, settings, fonts and SF Symbols. Chat with Android, Windows and Linux over LAN; exchange files and photos with receive permission, queues, pause/resume, native preview and sharing. Local history, drafts, delivery receipts, device consent, safety codes and QR verification are included. Mac and iPad gain adjustable native panes. Apple system peer-to-peer interfaces are enabled, while router-free physical-device acceptance and full Android parity remain ongoing.

### A terminal client with two ways to use it

NearbyIM Terminal runs independently of Java, a desktop GUI or the Android SDK. Its **TUI** offers keyboard-driven chats, nearby devices, files, search, history and drafts, with layouts that adapt to terminal width. Its **CLI** supports device discovery, text/file sending, transfer and trust management, JSON results, exit codes and shell completions for local workflows. Five-language help, onboarding and prompts are included. It uses its own identity/profile, starts with LAN listening off and preserves explicit trust/receive decisions.

### Everyday improvements

- Native text read receipts with a default-on opt-out, mutual enablement and actual foreground visibility; cyan `#66CCFF`, with a subtle dark-only glow. Terminal does not yet implement read receipts.
- Negotiated 32 KiB text, with the 8192-byte legacy limit retained; draft-saving fixes and removal of the persistent native composer byte counter.
- A lightweight Unicode emoji picker on Android/desktop, with categories, search, recents and skin-tone variants; immediate desktop language switching and five-language localization.
- Tablet/foldable controls, adjustable panes and snapping; Ubuntu22.04 AppImage compatibility; multihomed discovery and diagnostics; file recovery, bounded retry and route-decision improvements; clearer per-transfer measurements and diagnostic-ID privacy; Android gallery filename length handling.
- An official NearbyIM Agent Skill for CLI automation, plus Japanese and Korean README documentation.

See the full issue/PR index above and [eight native runtime screenshots](https://github.com/GHOST-AKU/wozai/blob/main/docs/screenshots/0.3.3-preview.4/README.md). Phones use portrait orientation. Open acceptance Issues do not erase shipped work, and merged features do not imply every physical-network or performance check is complete.

**Download note:** v0.3.3 ships the existing preview.4/build15 files without recompilation; filenames, internal version labels, signatures and hashes are unchanged. Existing users of those identical files do not need to reinstall. Use the download table above. Windows is not Authenticode-signed; Mac is ad-hoc without Developer ID/notarization; iPhone/iPad IPA requires re-signing. Apple requires macOS14 or iOS/iPadOS17. Original sources, hashes and outstanding limits remain in the provenance attachments and issue records; older Release assets are unchanged.

```sh
python3 tools/generate-i18n.py
python3 tools/version.py --check
```

历史 tag、附件和旧版发布工具中的固定来源是历史证据，不回写；`publish-native-preview` 工作流只属于已发布 preview.1，不用于发布新轮次。新轮次须单独核验来源、签名、哈希与安装说明。

## 正式发布条件

- 对候选平台核验包内版本、精确源提交、签名状态、安装/升级与数据保留、下载哈希和中英文说明。Apple 签名状态仍按实际产物披露。
- 不把已知无法启动的 AppImage 或尚未完成的中文帮助当作稳定支持；相关平台须修复阻断问题，或明确继续作为实验预览。
- 有线与无线互发现、临时 P2P 建链/真实择路收益/距离断路恢复、大文件与暂停/取消、平板双吸附、Apple 和 Terminal 流程补充真机证据。自动化不代替射频、驱动或存储提供者验收。

- 多设备并行 #6、LAN→P2P 重新升级 #36、群聊/Mesh/公网中继不自动扩入本轮。没有预设发布日期；实现、审查、构建通过和真机验收分别记录。

This is a **release plan**, not a published release or completed acceptance. [Issue #55](https://github.com/GHOST-AKU/wozai/issues/55) tracks scope and evidence.

Stable **v0.3.2** and the existing Apple/Terminal **v0.3.3-preview.1** retain their original assets. The prior preview.2/build13 and PR #61 retain their source-scoped evidence. The read-receipt development branch advances Android, Windows/Linux GUI, Apple and Terminal metadata together to **0.3.3-preview.3**. `i18n/config.json` owns the full version and build number; `tools/version.py --write` synchronizes Android code14, Apple numeric 0.3.3/build14 and Rust Cargo/lock versions. Regenerate Java resources with `tools/generate-i18n.py`. Windows/jpackage uses numeric 0.3.3, Debian uses `0.3.3~preview.3`, and application displays and package filenames retain the full preview identifier. Increment both preview.N and buildNumber for later rounds. Sync older implementation branches before rebuilding. A shared version does not imply identical capabilities.

Already merged since 0.3.2: recovery isolation and test integration (#37), bounded quality-request retries (#39), current-task recovery snapshots (#40), native SwiftUI Apple clients and streaming files (#35/#44), independent Rust TUI/CLI (#41), and preview packaging/install/README work (#45/#46 and later documentation).

Optional emoji and Agent Skill work (#52/#50/#51) stays separate.

The routing investigation must address the 128 KiB probe versus 1 MiB file window, STA/P2P concurrency bias, short sampling and modeled handover cost. Stable gates include usable packages/help, truthful signing and installation instructions, preserved upgrades/data, source/hash provenance, old-peer capability compatibility and physical network/file/UI evidence. Formal performance, end-to-end accounting (#32), long-term memory (#9) and audit limits stay explicit. Platforms with unresolved blockers remain experimental. No automatic release/merge, no promised ship date and no implied completion of native transport parity, multidevice chat, re-upgrade, group chat or Mesh. The historical preview.1 publishing workflow is archival and must not be reused to publish a new round.
