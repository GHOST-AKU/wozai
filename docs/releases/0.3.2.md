# 我在 · NearbyIM 0.3.2

0.3.2 正式版提供 Android、Windows x64 和 Linux x64 客户端。三端同步更新通信协议与界面，合并 PR #18 的加密、流式附件、文件选路、保存位置和大屏适配改动。

## 下载与升级

- Android：`NearbyIM-0.3.2-android.apk`，Android 8.0 / API 26 及以上，versionCode 12，固定签名、R8 优化、不可调试。可从同证书的 0.3.1 或 code11 预览包覆盖升级，保留应用数据。
- Windows：`NearbyIM-0.3.2-windows-x64.zip`，解压后运行 `NearbyIM/NearbyIM.exe`，保留原有用户数据目录。
- Linux：`NearbyIM-0.3.2-linux-x64.AppImage`、`.deb`、`.tar.gz`，均自带 Java。AppImage 支持无 FUSE 启动及持久桌面入口；系统依赖见附件 `LINUX-RUNTIME-REQUIREMENTS.txt`。
- `SHA256SUMS.txt` 和 `BUILD-MANIFEST.json` 提供每个发布文件的大小、SHA-256、统一来源与构建证据；`ANDROID-SIGNATURE.json` 提供 APK 独立核验结果。

通信双方都应升级到 0.3.2。NIM4 不回退到旧 NIM3 或明文，旧聊天记录和设备根身份保留。覆盖安装要求相同证书；不要通过卸载有聊天记录的应用来规避签名错误。

固定 Android 证书 SHA-256：`47a10fd5a882ab26c9a11fcc61df3b41f7c41017746fc6840cfbe581ca52c1dd`。

## 主要改动

- 文字、图片与文件使用 Noise XX / X25519 / AES-256-GCM 端到端加密，保留 P-256 设备根身份，并加入安全码与二维码核验。
- 单文件逻辑上限提升到 10 GiB，使用有界流式读写、持久检查点、SHA-256 和保存回执；支持多选队列、暂停/继续、失败重发及照片预览。
- 自动选择文件路径：复用已确认的端点热点，尝试原生临时 Wi-Fi Direct/P2P，再使用普通 LAN 或已有蓝牙。聊天连接模式保持 LAN/蓝牙，文件气泡显示真实数据路径及准备状态。
- Android 已知组协商通过加密聊天传递临时参数，优先 5 GHz，改进 VPN 排除判断、接口/IP 就绪及取消清理；修复暂停旧任务阻断建组能力回复，以及蓝牙聊天误使 Wi-Fi 文件沿用小窗口的问题。
- 独立 P2P 与 LAN 按实际加密吞吐比较；LAN 两轮均快至少 25%、预计净省至少 2 秒才换路。断路后自动尝试 LAN，按原任务和检查点继续；手动暂停/取消保持有效，身份或完整性失败不降级。
- Android 可授权接收文件夹，完整文件按原名另存、同名不覆盖；提供系统/浅色/深色外观、平板与折叠窗口基础适配，并改进扫码预览和对焦。
- 桌面附件保留原名、另存位置和实际传输路径；改进有线/Wi-Fi LAN 发现。Linux 新增 AppImage。五种语言同步更新，设备支持独立头像。

## 已知限制与验收边界

本次按维护者决定发布正式版，以下项目继续在 Issues 跟进，不能据正式发布状态视为全部验收通过：

- 小米 10S / 平板 6 已有两次原生 P2P 建链/选路成功记录，分别通过 LAN 与蓝牙协商；临时 P2P 的重复稳定性、真实吞吐比较、距离/半开断路恢复、无外部网络及清理仍待真机验收（#23）。临时 P2P 当前由 Android 实现；桌面原生 Direct 尚未实现。应用不自动开启普通热点。
- 桌面自动续传回归曾有一次 20 秒超时，后续单项与整组通过，首轮原因仍未定位，失败诊断已保留（#11）。
- 长期空闲/仅连接内存增长、温升与正式性能验收未完成（#9）；手机 10 GiB 原文件及更多厂商设备仍待验证。
- 平板/折叠基础适配已有用户确认，UI 细节、真实折叠设备和完整大屏验收继续完善（#25）。实体蓝牙与有线/Wi-Fi 互通验证范围见 #7、#5。
- 本地聊天记录与附件仍未加密存储，端到端加密不等于磁盘加密；尚未完成独立密码学审计。Windows 安装包未提供代码签名。

最终源提交、三端构建结果、固定签名与附件摘要以 GitHub Release 和 Issue #26 的发布证据为准。自动化回环、模拟器和受控平台替身不替代射频或厂商真机验收。

## English summary

0.3.2 ships matching Android, Windows and Linux clients with NIM4 end-to-end encryption, safety-code/QR verification, bounded streaming files up to 10 GiB, durable resume, batch sending, automatic file routing and actual-path indicators. Android adds a user-selected receiving folder, theme preferences and adaptive tablet/foldable layouts. Desktop packages preserve attachment names and save locations; Linux adds AppImage.

Android uses versionCode 12 and the persistent certificate. Upgrade both peers; NIM4 does not downgrade to NIM3 or plaintext. Preserve user data and verify the release checksums before installing.

Measured LAN selection and recovery after Direct loss are implemented, but device throughput, repeated P2P establishment, distance-loss recovery, offline acceptance, long-term memory and formal performance remain open. One intermittent desktop recovery timeout remains unresolved despite subsequent passing runs. Physical-device, large-file and security-audit limits are tracked in the linked Issues and are not waived by this stable release.
