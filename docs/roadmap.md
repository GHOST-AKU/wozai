# 「我在」产品路线图

本文按依赖关系安排后续工作。阶段是建议顺序，不代表已经开始或承诺发布日期；每阶段在实现前仍需补充具体设计与任务清单。

## 当前基线

0.2.0 已具备安卓一对一文字聊天、设备信任、历史会话重连和送达回执。根据 2026-10-02 的双机测试反馈，蓝牙与局域网互聊、已信任设备免重复确认和直接重连均已通过。此处记录的是用户报告的设备验收结果。

当前重要限制：NIM2 的签名用于身份连续性和消息完整性，不提供机密性；局域网消息为明文。Android 前台服务通知用于显示连接状态和维持连接，不等同于新消息通知。

当前用户反馈、已确认的连接人数限制和预览版待验收事项集中记录于 [未解决问题清单](open-issues.md)。后续排期优先依据这些条目的证据与状态。

## 全阶段质量要求

多语言与无障碍不是独立的收尾版本；从下一阶段开始，新界面和交互都应满足以下要求，并随每个里程碑验收。

### 多语言

- 将界面文案从代码中抽离，避免新增功能继续写死中文字符串。
- 使用平台 locale 能力格式化日期、时间、数字和复数；布局能容纳更长的翻译文本。
- 支持应用语言变化后刷新界面，不影响进行中的连接、会话、草稿或传输。
- 保持翻译键稳定，检查缺失文案和占位符；新增语言需完成核心流程的完整翻译。
- 首批语言及翻译流程待产品确认；简体中文作为现有基线，英语可作为候选首发语言。

### 无障碍

- 关键操作有清楚的屏幕阅读器标签、角色、状态和焦点顺序；图标按钮不可只有视觉含义。
- 支持系统字体缩放与高对比度，避免文字裁切、状态仅用颜色表达或触控目标过小。
- 输入区、会话列表、连接状态、传输进度和错误信息对 TalkBack 等读屏可理解。
- 键盘可操作桌面端主要流程；平板支持外接键盘、触控和窗口调整。
- 尊重系统减少动态效果偏好；提供动画关闭或静态反馈路径。

**每阶段验收门槛：**新增/修改的关键流程至少完成大字体、读屏标签与焦点、颜色对比、键盘或触控可达性检查；按平台记录未通过项，不把无障碍验证推迟到所有功能完成之后。

### 0.3 · 通信基础与安全设计

先明确后续附件和群聊共同依赖的协议边界，避免各功能各自扩展线格式。

- 设计协商版本和能力的方式，明确新旧客户端如何拒绝或兼容。
- 在传输图片、文件前设计并实现会话加密；签名和校验和本身不隐藏内容。
- 设计有界二进制分块、完整性校验、超时、取消及资源释放规则。
- 明确附件元数据、大小上限、文件名处理、存储位置和失败后的清理策略。

**完成标准：**协议测试覆盖分片/重组、长度边界、截断、乱序或重复块、篡改、取消及断线；未认证或协商失败的连接不能访问附件数据。

### 0.4 · 一对一图片与文件传输

- 在已连接的一对一会话中发送图片和普通文件。
- 展示待接受、传输中、完成、失败等状态，以及进度和取消入口。
- 对收到的图片提供预览；文件由用户选择保存或打开。
- 优先支持局域网和蓝牙，分别验证带宽、断连与系统存储授权行为。

**完成标准：**大文件不会一次性读入内存；接收端能检测不完整/损坏内容；取消或失败不会留下可误认为完整的文件；图片与文件双机互传通过。

### 0.5 · Android 消息通知

- 新消息到达时显示会话通知，点击可回到对应会话。
- 处理 Android 通知权限、通知渠道、勿扰偏好、前台/后台及应用内当前会话场景。
- 提供锁屏内容预览控制；通知权限关闭时应用内仍能查看消息。
- 保持附近设备本地通信，不依赖云端推送服务。

**完成标准：**前台、后台、进程恢复、权限拒绝和多会话场景均有验证；通知不会把消息送到错误会话或重复创建。

### 0.6 · 平板与大屏布局

- 根据可用窗口宽度自适应单栏或「会话列表 + 聊天详情」双栏。
- 支持横竖屏、分屏/自由窗口、窗口尺寸变化、键盘和触控操作。
- 保持手机布局清晰，不将平板布局简单缩放到手机上。

**完成标准：**手机与平板尺寸下列表、消息、输入区均可用；旋转或调整窗口后当前会话、草稿和阅读位置保持一致。

### 0.7 · 群聊

群聊开始编码前需要单独确定消息分发模型。可选方向包括成员设备互相直连/转发，或由群内设备承担局域网中继；附近网络的可达范围意味着群聊不天然具备互联网群组的在线能力。

- 定义群组创建、邀请、加入、移除和退出规则，以及群组身份如何验证。
- 设计成员变化后的密钥更新、消息来源标识、去重、送达状态与历史记录。
- 明确设备离线、成员不在同一网络、发起者离线时的实际行为；界面如实呈现未送达状态。
- 先交付附近网络内可测试的群组 MVP，再评估跨网络转发能力。

**完成标准：**成员变更和断线场景不会静默泄露后续消息；重复、乱序和未送达状态可解释；多台设备群聊通过测试。

### 后续 · Windows 与 Linux

2026-10-02 根据新的开发方向，已提前开展 Windows 文字预览版：复用现有 NIM2 核心，完成 Android 0.2.0 兼容、桌面身份/信任、发现、记录和便携打包；按用户 Windows 双机测试反馈，继续迁移安卓视觉设计、图标、经典蓝牙与软件旁的数据目录。范围及验证见 [Windows 说明](windows.md)。2026-10-03 已交付 Linux 0.3.1 预览版，包含局域网、BlueZ 蓝牙桥接及自带运行时的 tar.gz／deb 包，见 [Linux 说明](linux.md)。三端已发布 [0.3.1 Preview 1](https://github.com/GHOST-AKU/wozai/releases/tag/v0.3.1-preview.1)。此轮不代表附件、群组或会话内容加密已完成，Windows／Linux 蓝牙真机互通仍待验收。

协议、附件和群组边界稳定后再扩展桌面端完整功能矩阵，尽可能复用与 Android 无关的 Java 协议核心。

- 先做技术验证：桌面 UI 技术、复用现有 Java 核心的边界、安装包和签名/分发方式。
- Windows 与 Linux 均已加入经典蓝牙 RFCOMM 桥接，跨平台真机验收仍待完成；有线网络发现问题与同时多人私聊限制见未解决问题清单。
- 复用设备身份和协议测试；设计桌面端密钥安全存储、升级、日志与卸载行为。
- 确定手机与桌面端之间的身份信任、设备撤销和跨平台附件/群聊兼容规则。

**完成标准：**Windows 与 Linux 均可安装、发现附近设备、完成可信连接和文字互聊；平台特有权限、网络变化与应用退出行为有测试记录。

## 依赖与并行关系

| 工作 | 依赖 | 可并行的部分 |
| --- | --- | --- |
| 会话加密与协议能力协商 | 当前 NIM2、信任身份 | 先做协议设计与平台调研 |
| 一对一附件 | 加密会话、分块协议、存储策略 | 图片/文件 UI 原型可先行 |
| Android 消息通知 | 消息入库与会话路由 | 可与协议设计、平板布局并行 |
| 平板布局 | 稳定的会话状态与导航 | 可与通知、附件协议设计并行 |
| 群聊 | 群组身份/密钥/分发模型；建议复用附件传输框架 | 桌面技术验证可并行 |
| Windows/Linux | 稳定协议核心、身份与兼容规则 | 可提前做小型技术验证，不先承诺完整功能矩阵 |

## 暂不纳入近期范围

互联网中继、云端账号与同步、语音/视频通话、自动重发，以及跨互联网的群聊在线保证。若产品方向变化，再单独评估其服务器、隐私和运维成本。
