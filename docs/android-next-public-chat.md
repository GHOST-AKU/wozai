# Android Next 公共聊天体验（0.4.0-preview.8）

## preview.12 自动连接

- 公共聊天首次开启会说明公开范围和自动接收。允许后，打开应用会用上次选择的方式恢复接收。聊天页或通知里的「停止接收」会取消自动恢复。切换页面时接收继续运行。每次启动中继处于关闭状态。
- 「私聊设备」可分别启用局域网和蓝牙的自动接收。受支持的无线功能恢复可用或重新打开应用时会恢复已启用的接收。进入设备选择会短暂搜索设备，进入已记住的会话会自动尝试连接。系统蓝牙的首次配对和可发现性仍由系统控制。
- 对方首次请求会在页面顶部显示「拒绝」「仅本次」「接受并记住」。已记住且仍能证明同一公钥的来访设备自动接入，阅读中的页面可以继续使用。
- 私聊同时只有一条活动连接。自动切换会等待尚未处理的请求、文件和未确认消息完成。在当前会话按下发送后会等待已选对象完成握手。取消、超时、离开会话或身份不符时，文字留在原草稿。草稿会保留，待连接的临时发送指令跟随当前界面。
- 进程被系统停止后，下次打开应用时恢复已授权接收。当前包使用原有 NIM4 记录和私聊数据库格式。

## preview.8 记录

本轮基于 main `4851754`（已合并 #109），只改 Android Next 的公共聊天界面与告知流程。#101 自动私聊设计、#103/#108 Apple Draft 不在本轮范围内。保留现有会话/附近/设置导航，公共聊天在“附近”，私聊设备入口继续保留。

## 使用方式

- 聊天列表、私聊和「附近」的顶栏网络图标进入同一个私聊设备页。图标显示实际私聊链路。公共接收运行时，角标实时显示已完成握手的 Mesh 直连设备数，包含零。这个数字按节点计数，覆盖范围为本机的直接连接。
- 点击“开启接收”。首次显示公开范围、接收方式和临时历史说明；之后只需手动开启与满足系统权限。应用重启不自动开启，中继每次默认关闭。
- 开启即自动发现、连接、接收和发送公共消息，无需逐条同意。可切换页面继续运行；页面或常驻通知均可停止。
- 聊天选项显示本机系统报告支持的传输方式，硬件不支持的方式不可选择。硬件支持不代表已授权、无线已开启或已经连上；这些仍由现有 guard 和运行时检测。
- 蓝牙模式沿用手机 BLE CoC 与 Windows RFCOMM。Windows 首次搜索时，在选项点“让电脑发现”，允许系统提示；手机间接收不再被这个额外弹窗打断。Wi-Fi Aware 是独立模式，双方需支持并选择同一方式，不是普通 Wi-Fi/热点。
- 中继、电脑可发现与 TXT 诊断移入选项。主界面显示关闭、启动、寻找附近设备或已连接的直接邻居数。直接邻居数不是全网在线人数。

## 消息与历史

公共消息不是端到端加密；参与者和中继可以读取。签名验证不是本人身份核验，也不会建立 NIM4 私聊信任。

Android Next 发送时使用设置里的设备昵称，随公开消息一起传播。昵称作为 `[WoZai Mesh] 昵称` 首行进入原发送者签名覆盖的正文。旧中继可原样转发，旧客户端仍能在正文首行阅读昵称。Android Next 单独展示昵称，旧消息和无有效昵称的消息显示发送节点的公钥缩写。昵称是发送者自报的公开称呼。正文的可用字节数会扣除昵称首行所占的空间，公用报文仍以 2048 个 UTF-8 字节为上限。

“等待邻居接力”只是已获 Core 接受；“已交给邻居”仅为下一跳接手，不是全网送达或已读。过期、停止未确认与已接收分别显示；自己的消息不再显示没有实际意义的“0 跳”。输入只在新消息已获接受且仍匹配原输入时清除，失败保留文字。

历史沿用原有 `MeshHistory` 的边界：**仅当前应用进程、最多 200 条**，超过上限移除最早消息。切页、旋转、停止/重开 Mesh 保留当前进程的历史；进程退出、被系统结束、覆盖安装后重启会消失。历史留存不延长转发期限，消息过期也不主动删除界面历史。主页面的临时历史入口可查看完整规则。

## 数据与覆盖安装

包名仍为 `dev.ghost.nearbyim.next`。不修改或清理私聊数据库、身份、密钥、信任、设置及 Mesh `files/mesh-v1` profile；只增加 `mesh-preview` 偏好中的版本化告知标记。原经典 Android 客户端与 Next 仍是两个独立沙箱，没有数据导入承诺。

安装交付必须通过 `tools/verify-android-signature.py --next`，保持持久证书 pin、非 debug 属性与原包名，版本递增至 preview.8/build23。这样可覆盖同证书的 Next；不要求卸载或清数据。临时公共历史从来没有持久化，覆盖安装重启不保留它，不能将其描述为持久聊天记录丢失。

## 验证边界

Android/Windows 公共蓝牙 Mesh 与中继已有所有者实机成功反馈，沿用[实机证据索引](mesh/field-validation-2026-11-08.md)。本轮不要求重复同样无线测试；新的界面自动化和签名构建不扩大 Wi-Fi Aware、Apple 或完整 #91 物理隔离验收范围。

本地 Robolectric 使用从成功运行 `42372287886` 的持久签名 APK 提取的原生 Core，逐一核对 Rust 输入与 ELF SHA-256：`fc82b8c4c788f1eb978552aff8ff1cb9cbba273d1bafcf613c1443a790c10b09`。它不是本轮重新编译的 Core。最终安装包由现有 CI 签名步骤构建，私钥不离开该步骤。具体构建提交、测试结果、artifact 与 APK 签名报告记录在交付 PR。

测试初期失败记录保留于本地日志：离线环境缺 Kotlin 插件、只读用户目录阻止 Robolectric 下载锁。修复测试缓存路径后，相关测试可正常运行；不把这些环境失败计作产品验收失败或成功。

提交前本地最终 Mesh 相关测试 37 项通过（含短窗口大字号与直接打开历史规则）；内部截图由 Robolectric 绘制，不是真机图。历史入口测试先暴露“只打开选项、规则未直接显示”，随后改为独立规则弹窗并通过回归。CI 完整测试、release lint 和持久签名以 PR 中的最终运行结果为准。
