# 「我在」UI 策划方案

日期：2026-10-01，修订于 20:55（Asia/Shanghai）。状态：设计提案；当前参考为用户调整后的浅色首页，交互继续细化。本轮只更新设计方案，没有修改安卓界面或连接代码，也没有编译 APK。

## 设计目标

让用户打开应用后能立即找到以前的聊天，也能清楚地发起一次附近连接。界面采用聊天应用熟悉的列表、搜索和底部导航。首次建立联系时确认并记住设备，后续重连直接聊天，蓝牙和局域网共用这套操作方式。

依据：用户提供的 WhatsApp 安卓深色聊天首页截图、「我在」现有功能和已确定的纸杯电话图标。对 WhatsApp 的观察仅来自这张截图；没有据此推断它的其他页面或最新产品行为。示意内容均为虚构联系人与消息。

## 从参考截图中学习什么

| 参考中的设计 | 对「我在」的用途 | 具体安排 |
| --- | --- | --- |
| 标题、搜索、会话列表的纵向层级 | 打开就能理解页面目的 | 首页标题「我在」，搜索在列表上方，不放大面积介绍文字 |
| 头像、昵称、摘要、时间的固定位置 | 快速扫视多条会话 | 头像靠左，昵称与摘要共用文本起点，时间右对齐 |
| 列表行共用一个背景 | 减少视觉碎片 | 不给每个联系人套卡片，优先用间距和对齐分组 |
| 一个醒目的新聊天浮动按钮 | 发起聊天的明确入口 | 点击进入「附近」，由用户选择连接方式 |
| 底部导航与选中图标的胶囊底色 | 切换主要页面 | 三项：聊天、附近、设置；消息详情隐藏底部导航 |
| 深色背景、主次文字和少量绿色 | 降低信息噪声 | 我们采用偏薄荷的绿色，并提供浅色视觉方向 |
| 过滤标签 | 会话多时缩小范围 | 首版先不放标签；未读计数完成后再考虑「全部 / 未读」 |

「我在」当前是一对一文字聊天。页面围绕这些功能展开，不加入动态、社群、通话、群聊、相机、语音或附件入口。草稿、回执和离线历史也要按真实能力呈现。

## 页面结构

底部三项：**聊天 / 附近 / 设置**。聊天详情作为会话的下一层页面。现有「记录」的内容并入聊天首页，设置从菜单升级为独立页面。

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 聊天首页 | 会话列表、搜索、当前连接标记 | 打开会话；右下角新聊天按钮进入附近 |
| 附近 | 局域网 / 蓝牙切换、接收状态、设备列表 | 搜索设备，选择对方并申请连接 |
| 聊天详情 | 对方昵称、实际连接状态、消息、输入栏 | 发送文字；菜单内断开与清空当前记录 |
| 设置 | 本机昵称、已信任设备、权限入口、使用说明、停止连接 | 修改昵称、管理信任、已有连接和权限 |

「附近」只是设备发现页。设备出现在扫描结果中时显示「已发现」，不显示「在线」；首次确认或已信任设备自动验证完成、会话可以发送后才显示「已连接」。当前版本同时只有一位正在聊天的连接对象，首页其他会话属于本机历史。

## 聊天首页

- 顶部左侧标题为「我在」，右侧为紧凑的连接方式图标和状态文字，例如「局域网 · 已连接」。移除页头纸杯电话图标和重复品牌文字；APP 启动图标保留原有白色底板和纸杯电话图案。
- 顶部指示对应实际聊天连接状态，不能仅因手机连着 Wi-Fi 就显示「已连接」。没有聊天连接时显示「未连接」，连接过程中显示「连接中…」；接收状态仍在附近页单独显示。
- 默认按最近会话活动排序。列表行包括默认头像、昵称、最后一条消息摘要和时间；长昵称、长摘要只显示一行并省略。
- 默认头像由昵称首字和稳定的颜色生成。概念图中的插画头像只是视觉示例，自定义头像上传不属于首版任务。
- 当前已连接的会话显示小圆点和「局域网」或「蓝牙」文字。状态不只靠颜色区分，且只有连接完成后才出现。
- 点击历史会话先立即打开本机记录。对已信任设备可直接点「连接」尝试重连，省去前往附近页、重新选择设备和双方再次同意；连接中保留输入能力，但连接成功前不能发送。已经连接该设备时直接继续聊天。
- 蓝牙重连使用已记录且仍有效的设备地址；局域网重连通过发现服务解析当前地址，不能把旧 IP 当成设备身份。找不到对方时留在记录页，显示「暂时无法连接」与「重试 / 去附近查找」操作，不弹出重复确认。
- 右下角仅有一个新聊天按钮，读屏名称为「新聊天」。点击进入附近页，保留用户上次选择的连接方式。
- 空列表展示文字「还没有聊天」和辅助说明「找到身边的人，聊第一句话。」主要按钮为「找附近的人」。界面不额外放纸杯电话图标，空态时也不重复显示第二个相同功能的大按钮。
- 搜索首期只搜索本机会话昵称。消息全文搜索另行设计，避免结果混杂。无结果显示「没有找到相关聊天」，允许清除关键词。

会话摘要、搜索和未读均需在后续实现中补充查询或状态逻辑。当前会话对象只包含身份、昵称和更新时间，不能直接把更新时间当成最后消息时间。

## 附近页

标题「附近」，标题下为「局域网 / 蓝牙」分段选择，随后是精简的接收状态行与设备列表。页面只为当前连接方式展示相关操作。

**局域网模式**

1. 说明「两部设备连接同一 Wi-Fi，或加入同一个热点」。
2. 接收状态行显示「接收已关闭 / 正在接收」，提供明确的开启或关闭操作。接收开启后可展开查看本机 IP 与端口并复制。
3. 主要按钮「搜索设备」；扫描时变为「正在搜索…」并提供停止操作。设备列表下保留次要文字入口「通过 IP 地址连接」。
4. 发起连接时显示简短说明「局域网消息以明文传输，请使用可信网络」。说明放在相关步骤，不占据每个主页面的大块空间。

**蓝牙模式**

1. 说明「对方开启接收并允许被发现后，再开始搜索」。
2. 展示实际蓝牙开关与权限状态。需要系统配对时明确告知，让系统处理配对界面。
3. 主要按钮仍为「搜索设备」，次要操作「允许被发现 120 秒」，并显示真实剩余时间。
4. 权限被拒绝或设备不支持蓝牙时，提供对应的权限入口或切换局域网操作。

切换分段仅切换查看和发现模式，不应默默断开正在进行的聊天。若后续底层切换必须停止接收，要在实际操作时说明影响并保留用户的控制。

设备行包含默认头像、昵称、连接方式与可选的地址信息。整行可以点击，避免为每个设备同时放多个小按钮。地址等技术信息在需要区分重名设备时展示或展开。已信任设备可在状态行标注「可直接连接」，不再以「首次聊天」流程处理。

## 连接与记住设备

核心规则：**首次认识时确认；记住以后直接连接。** 已有聊天记录、系统蓝牙已配对、当前已连接是三个不同状态，界面分别表达。

| 情况 | 发起方操作 | 接收方操作 |
| --- | --- | --- |
| 首次连接 | 点击设备并发起聊天，点击本身即为本次同意；不再额外问一次「是否同意聊天」 | 显示确认面板，主要操作「同意并记住」，次要操作「拒绝」；提供「仅本次」选项 |
| 双方已记住且身份验证通过 | 从历史会话点「连接」或点击附近的同一设备，连接成功直接聊天 | 接收已开启且当前空闲时自动接受，不弹应用内同意面板 |
| 一方选择过「仅本次」或取消信任 | 继续正常发起连接 | 没有持续授权的一方按首次授权流程确认；另一方无需重复确认 |
| 蓝牙系统已配对，但从未在「我在」里聊过 | 可直接尝试服务连接 | 仍进行第一次应用内同意，不能仅因耳机等系统配对记录就认可聊天身份 |
| 暂时找不到对方 | 保留本机记录和草稿，显示重试入口 | 无操作，不产生确认弹窗 |

首次接收面板文案：「小林想和你聊天」，下方写明连接方式，并说明「记住后，下次可以直接连接。可在设备信息中取消信任。」选择「同意并记住」后，只有会话实际建立成功才保存持续授权；拒绝、取消、超时或验证失败不会写入信任。发起方的连接页面也说明成功后会记住该设备，并允许选择仅本次。

首次连接仍执行双方协议就绪握手。发起方不需要再点一遍确认，点击发起已表达同意；受信任的后续连接自动执行本机就绪步骤，但不能跳过协议、身份验证或对方的授权状态。

已信任重连不要求对方反复打开「允许被发现」。已配对蓝牙设备可用已知地址尝试连接，但对方必须在范围内、开启蓝牙并运行接收服务；这不承诺对方应用被关闭时仍能连上。局域网也仍要求网络可达和接收服务开启。

本轮不增加持续扫描所有老设备或断开后无限重试。重连由用户发起，或在用户此前授权且接收开启时接受对方请求。对方关闭接收、应用停止服务或撤销授权后，不自动打开相关功能。

接收已信任连接后更新状态，不强制把应用带到前台，也不抢走用户正在看的设置或历史页。新消息以消息提示和现有通知机制呈现。发起方连接成功后进入对应会话。

若已有另一位连接对象，不接受新连接来替换对方。主动切换时让用户明确选择结束当前连接，再连接目标；后续仍是一对一会话，不暗示多路连接。

## 设备信任与身份

信任是一项本机持续授权，应独立于聊天内容保存。清空消息、改昵称、换 IP 不取消信任；在设备信息中选择「取消信任」后，下次来访需要重新同意。用户如选择「取消信任并断开」，同时结束当前会话；单纯断开则保留信任。

信任只代表同意与先前认可的同一个应用设备身份再次聊天，不认证对方的真实姓名。识别应绑定设备密钥，而不是昵称、IP 或对方自行填写的 UUID。计划为首次成功连接记录对方公钥，后续通过绑定当前会话的密钥证明验证同一身份，蓝牙和局域网使用同一身份记录；同名设备或身份验证失败不自动放行。具体握手与会话完整性保护需在实现时另行审查，本 UI 方案不等同于已经完成安全协议设计。

当前代码的 `HELLO` 只有 UUID 和昵称，`onHello` 每次都会创建同意弹窗；没有公钥证明和独立信任记录。会话表还可能在同意后、连接完成前写入，因此「有历史会话」不能直接当成「已成功建立且持续授权」。这轮只修改方案，不把现有实现描述为已经支持自动重连。

旧版历史中的设备需在升级后通过一次有效身份绑定才能获得免确认授权，不能把旧的自报 UUID 静默转换成可信设备。旧聊天记录仍正常保留和查看。身份密钥重置、重装或清空数据后，如果无法证明原身份，则需要重新认识；新的信任不能悄悄覆盖原身份记录。

首次采用的记住设备方式属于首次使用时记录身份，并不验证真实身份，也不自动使局域网消息具备端到端加密。相关说明依然按实际实现能力显示。

技术参考：Android 官方说明，[已配对设备可通过已知地址直接尝试连接，配对与连接是不同状态](https://developer.android.com/develop/connectivity/bluetooth/find-bluetooth-devices)；[Android Keystore 提供应用密钥生成、签名和验证能力](https://developer.android.com/privacy-and-security/keystore)。这些资料支持实现基础，上述记住设备流程是「我在」拟采用的产品设计。

## 聊天详情

- 紧凑顶栏：返回、头像、昵称，第二行显示「已连接 · 局域网 / 蓝牙」或「未连接」。右侧菜单提供断开、清空本会话记录和设备信息；设备信息内可查看或取消信任。
- 左边为收到的消息，右边为自己的消息。气泡最大宽度约为可用消息区域的 78%，按窗口宽度计算；短消息不强行拉满。
- 收到气泡用中性表面色，发出气泡用低饱和绿色，聊天背景保持安静。日期分隔用小字号居中显示。
- 每条自己的消息旁保留真实发送状态：「待确认」「已送达」「未确认」。已送达表示对方已保存消息，不能表示对方已读。不做蓝色双勾或端到端加密锁的暗示。
- 输入栏固定在内容底部，键盘出现后位于键盘上方。输入框可从一行增长到四行，超过后在框内滚动；与发送按钮保留 8dp 间距。
- 空输入时发送按钮不可用；已信任设备未连接时提供「连接」入口，陌生或尚未绑定身份的设备提供「去附近连接」。保留已输入文字，避免用户误认为消息已排队等待自动重发。
- 当前的会话切换草稿保留行为应继续保留。重启后永久保存草稿属于后续增强，现有 SQLite 结构没有草稿字段。
- 读历史时收到新消息，不强制把用户拉回底部；显示「新消息」入口。已经在底部时才随新消息滚动。
- 清空记录放在菜单中，需要明确的确认提示；断开连接不清空历史。

## 设置页

采用简单分组列表：本机昵称、已信任设备、应用权限、停止所有连接、使用说明、关于「我在」。昵称修改复用现有长度限制。

「已信任设备」列表显示昵称、最近连接时间以及可直接连接的授权状态。点击进入设备信息，可以取消信任。清空聊天与取消信任各自说明影响，不混为同一个删除操作。

连接和聊天操作仍在相应页面完成。清空当前会话记录放在该会话的菜单中，避免在全局设置页造成对象不明确。浅色与深色均在本方案中探索；若后续增加主题切换，应列为新增设置功能。

## 建议的视觉规格

以下是我们的设计起点，不是从截图测得的 WhatsApp 官方规格。概念图用于选择方向，后续精确设计仍需按这些规格校准。

| 项目 | 建议值 |
| --- | --- |
| 页面左右边距 | 20dp，小屏可降为 16dp |
| 主要间距 | 4 / 8 / 12 / 16 / 24dp |
| 顶栏内容高度 | 56–64dp，系统栏留白另行处理 |
| 会话行 | 约 80dp，适配大字体后允许增高 |
| 列表头像 | 48dp，默认首字头像 |
| 搜索栏 | 48dp 高、胶囊形圆角 |
| 正文 / 摘要 | 15–16sp |
| 会话昵称 | 17sp，适中粗细 |
| 时间 / 状态 | 12–13sp，保留足够对比 |
| 触控区域 | 至少 48×48dp；图标可为 24dp |
| 浮动操作按钮 | 56dp，圆角约 18dp |
| 深色背景 / 表面 | #101619 / #222B2F |
| 深色主文字 / 次文字 | #F1F5F3 / #9AA8AD |
| 深色强调色 | #82D8BA，按钮上使用深色文字 |
| 浅色背景 / 表面 | #FAFCFA / #EEF3EF |
| 浅色主文字 / 次文字 | #17211C / #58675F |
| 浅色强调色 | #246B4E，强调文字与浅底分离 |

APP 启动图标保留黑色纸杯电话和白色圆角底板；白色是图标的一部分。按用户修订，首页页头和空态不展示该图标，页头仅保留左侧「我在」和右侧连接指示。

## 动画与特效

动画用于说明状态变化。以下时长是待真机验证的起点。

| 场景 | 设计 | 建议时长 |
| --- | --- | --- |
| 按下按钮或列表行 | 轻微涟漪，颜色反馈 | 100–150ms |
| 底部导航切换 | 选中底色与图标色过渡 | 150–180ms |
| 会话列表进入聊天 | 顶栏与内容的短距离过渡 | 180–220ms |
| 新消息到达 | 透明度变化，最多 4–8dp 的位移 | 120–160ms |
| 连接确认面板 | 底部滑入与淡入 | 200–240ms |
| 正在搜索 | 一个小进度指示；发现设备后停止 | 仅搜索期间 |

首版不使用持续背景粒子、全屏雷达、毛玻璃、循环发光或每个气泡的弹簧动画。优先动画透明度与短距离位移，避免让整张聊天列表反复测量布局。减少动画设置开启时只保留即时状态反馈。

效果是否影响性能要在实现后测量；图片概念不能证明帧率。建议验收普通 60Hz 安卓设备的键盘展开、列表滚动和消息到达过程，再评估是否需要复杂特效。

## 关键状态与适配

| 情况 | 界面响应 |
| --- | --- |
| 没有历史 | 明确的空态与「找附近的人」入口 |
| 搜索不到设备 | 说明当前连接方式的前提条件，允许重试 |
| 蓝牙关闭 / 权限未授权 | 只展示当前操作所需的授权入口 |
| 接收开启但尚未连接 | 附近页显示「正在接收」，不把联系人标为在线 |
| 首次等待对方同意 | 显示对方昵称、等待状态与取消入口 |
| 已信任设备重连 | 只显示连接进度；验证与就绪完成后直接聊天，不弹同意面板 |
| 设备身份变化 / 信任已取消 | 不沿用免确认授权，需重新同意 |
| 连接中断 | 聊天页保留消息和输入内容，显示重新连接入口 |
| 未收到回执 | 状态为「未确认」，不自动重发或宣称发送失败 |
| 保存消息失败 | 显示保存失败，不显示已送达 |
| 键盘展开 | 输入栏位于键盘上方，最新消息仍可见 |
| 小屏 / 横屏 / 分屏 | 基于当前窗口布局，状态和操作允许换行 |
| 大字体 | 行高增长、按钮不截字，不以省略掩盖重要操作 |
| 系统手势区域 | 内容与底部操作避开实际系统 Insets |

新消息时间使用真实消息时间。昵称重名时在连接前提供地址或本机身份信息帮助区分。颜色之外保留文字状态，所有纯图标按钮有读屏标签。

## 三个首页视觉方向

1. **熟悉的深色列表**：完整搜索栏、统一的平铺会话行、新聊天浮动按钮。重点是易理解的聊天入口，最接近用户提供截图的组织方式。
2. **当前连接优先**：紧凑搜索入口，把唯一已连接会话放在上方的独立列表分组，其他历史排列在下方。重点是立即找到正在聊天的人。
3. **轻盈的浅色列表**：浅色界面，完整搜索与简洁的最近会话分组，使用带文字的新聊天按钮。按用户修订，左上标题为「我在」，右上为「局域网 / 蓝牙」连接指示，移除页头纸杯电话图标与重复品牌文字。

前两项为已探索的备选方案。当前继续围绕用户调整后的第三项浅色首页细化交互。无连接时，第二个方向的「当前连接」分组应自动隐藏，不留下空卡片。
