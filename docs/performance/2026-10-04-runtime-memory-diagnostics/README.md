# Runtime memory diagnostics

Separate instrumented runs of the same two app-images used in the six formal trials. See [metadata.json](metadata.json) and [the performance report](../../performance.md#pr-10linux-runtime-与空闲内存2026-10-04) for the pinned application, runtime, environment and scope. These observations do not use the modified branch application JAR.

Each state/level starts a fresh JVM and profile. Add `-XX:NativeMemoryTracking=summary` to both runtimes. For Idle, launch the native packaged `bin/NearbyIM --performance-ready-file <marker>` with `-Dwozai.dataDir=<fresh temporary profile>`; timing starts after the GUI marker. For Connected, run the existing compiled `PerformanceScenario peer <temporary directory>` and `PerformanceScenario target <directory> <endpoint from peer.json> <id from peer.json>` using that image's runtime and application classpath plus `desktop/build/tests`; timing starts at `phase.json` = `connected`. Send no `active` command. Stop both through the existing probe / scenario shutdown paths.

At 30, 90 and 180 seconds, read target RSS and `psutil.Process(pid).memory_maps(grouped=True)`, then run the same JDK's `jcmd <pid> VM.native_memory summary` and `jcmd <pid> GC.heap_info`. Classify paths ending in `/lib/modules` as `runtime_modules`, `[anon]` / `[heap]` as `anonymous`, and other mappings as `other`. Connected also samples RSS every five seconds. `snapshots.json` preserves the actual elapsed times and mapping totals; reading maps and process RSS is not atomic.

Only after the last pre-GC observation run `jcmd <pid> GC.class_histogram`, then record a separately labelled post-GC snapshot. The histogram's `Total` is live object bytes after a full GC, not committed heap or process RSS. Instrumentation, attachment, compiler activity, collection and page residency can change RSS; do not replace the uninstrumented formal samples with these values. Every original NMT / heap report and histogram is retained here.

Post-experiment self-review verified the preserved runtime copies have identical relative file paths and only `lib/modules` differs in content. The full per-file SHA-256 comparison is in [runtime-comparison.json](runtime-comparison.json). Connected peak RSS must be calculated from every pre-GC observation in `snapshots.json`, not only the three mapping snapshots. The `note`-labelled post-GC observation is excluded.
