# 我在 · NearbyIM

[简体中文](../../README.md) | [English](README.en.md) | [日本語](README.ja.md) | **한국어**

**원격 서버를 거치지 않고도, 서로 편하게 대화하세요.**

**我在(Wozai, NearbyIM)**는 가까운 기기끼리 직접 통신할 수 있도록 만든 오픈 소스 채팅 앱입니다. 정식 버전은 Android, Windows, Linux에서 **LAN(로컬 네트워크)** 및 **클래식 블루투스(Classic Bluetooth)** 연결을 지원합니다. 프리뷰 버전에는 **macOS, iPhone, iPad용 네이티브 클라이언트**와 **Windows/Linux용 Terminal(TUI/CLI) 클라이언트**가 추가되었으며, 현재 주로 LAN을 통해 상호 통신합니다. 계정을 만들거나 클라우드 채팅 서버를 이용할 필요가 없습니다.

**이후 새 빌드에는 Android, Windows/Linux GUI, Apple, Terminal 모두 `0.3.3-preview.2` 버전을 사용합니다.** [0.3.3 개발 계획](../releases/0.3.3.md)과 [범위 및 검수 기준 #55](https://github.com/GHOST-AKU/wozai/issues/55)를 참고하세요. 이는 현재 소스 코드의 개발 버전이며, 새 패키지는 아직 배포되지 않았습니다. 위 다운로드 링크는 이미 공개된 릴리스를 가리킵니다.

**0.3.2 정식 버전이 출시되었습니다.** Android, Windows, Linux의 프로토콜과 UI가 함께 업데이트되었으며, Linux에는 AppImage / deb / tar.gz 패키지가 제공됩니다. Noise 종단간 암호화, 최대 10 GiB 파일의 메모리 사용량을 제한한 스트리밍 전송과 영구적인 이어받기, 자동 파일 전송 경로 선택, Android 수신 폴더 설정, 태블릿·폴더블 기기의 기본 레이아웃 대응이 추가되었습니다. 변경 사항과 검수 범위는 [0.3.2 릴리스 노트](../releases/0.3.2.md)를 참고하세요. P2P 안정성, 실제 기기의 전송 속도 및 거리 변화에 따른 연결 복구, 장시간 메모리 사용량, 정식 성능 검증은 [#23](https://github.com/GHOST-AKU/wozai/issues/23)과 [#9](https://github.com/GHOST-AKU/wozai/issues/9)에서 계속 다루고 있습니다.

## 🌱 왜 「我在」를 만들었나요?

많은 채팅 앱은 인터넷 연결, 사용자 계정, 원격 서버가 당연히 있다고 가정합니다.

「我在」는 다른 길을 찾습니다. **두 사람이 바로 가까이에 있다면, 기기끼리 직접 대화하면 안 될 이유가 있을까요?**

지금은 단순하고 이해하기 쉬운 근거리 통신에 집중합니다. 기기가 서로를 발견하고, 신뢰할지는 사용자가 직접 결정하며, 메시지와 첨부 파일은 기기 사이에서 바로 전송됩니다. 어차피 두 기기가 서로 곁에 있으니까요. (｡•̀ᴗ-)✧

## 🏡 이런 곳에서 사용할 수 있어요

- **내 기기 사이에서 자료 옮기기:** 휴대폰에서 컴퓨터나 태블릿으로 글, 사진, 파일을 보냅니다. 클라우드에 먼저 업로드하거나 같은 제조사의 기기를 사용할 필요가 없습니다. 같은 LAN이나 핫스팟에 연결하면 됩니다.
- **사무실, 교실, 작업실에서 소통하기:** 같은 네트워크에 있는 동료나 친구와 일대일로 대화하고 문서 및 작업 자료를 주고받습니다. 네트워크가 기기 간 통신을 허용한다면 유선 이더넷으로 공유기에 연결된 컴퓨터도 참여할 수 있습니다.
- **인터넷이 없는 임시 현장:** 전시회, 행사장, 야외 협업 현장에서 기존 공유기나 직접 켠 핫스팟으로 로컬 네트워크를 구성할 수 있습니다. 인터넷 연결은 필요하지 않습니다. 클래식 블루투스를 지원하는 클라이언트에서는 블루투스 문자 채팅도 시도할 수 있습니다.
- **회원가입 없는 근거리 대화:** 주변 기기를 발견하고, 연결 및 기기 식별 정보 저장 여부를 양쪽 사용자가 직접 결정합니다. 채팅 기록과 수신 파일은 각자의 기기에 보관됩니다.
- **터미널과 스크립트 작업:** Windows/Linux 터미널에서 채팅하거나 파일을 주고받고, CLI의 JSON 출력 및 종료 코드를 로컬 스크립트와 연계할 수 있습니다. SSH로 조작하는 경우 기기 검색 및 연결은 원격 호스트가 속한 네트워크에서 이루어집니다.

현재 「我在」는 **기기끼리 직접 연결할 수 있는 일대일 통신**을 대상으로 합니다. 인터넷 중계, 그룹 채팅, Mesh/다중 홉 전달은 지원하지 않으며, 신뢰성이 보장된 기존 긴급 통신 수단을 대체할 수 없습니다. 플랫폼에 따라 지원하는 연결 방식과 기능이 다릅니다. Apple 및 Terminal 클라이언트는 현재 프리뷰이므로 아래의 플랫폼별 상태를 확인하세요.

## ✨ 지금 사용할 수 있는 기능

다음 내용은 주로 Android / Windows / Linux 정식 버전을 설명합니다. Apple 및 Terminal의 프리뷰 지원 범위는 플랫폼별 상태를 참고하세요.

- **LAN 직접 연결:** NSD / mDNS 자동 검색과 IP 주소 + 포트 직접 연결
- **클래식 블루투스 통신:** 보안 RFCOMM을 통한 기기 검색, 페어링, 재연결
- **플랫폼 간 채팅:** Android, Windows, Linux에서 공통 NIM4 암호화 프로토콜 사용
- **텍스트, 이미지, 파일:** 채팅 내 이미지 표시, 앱 안에서 보기, 최대 10 GiB의 메모리 사용량을 제한한 스트리밍 전송, 다중 선택 대기열, 일시 정지·이어받기·실패 후 재시도
- **자동 파일 전송 경로 선택:** 기존 기기 핫스팟 재사용, 임시 P2P·LAN·기존 블루투스 연결 시도, 연결 품질에 따른 LAN 선택, 중단 후 체크포인트부터 이어받기 및 채팅 말풍선의 실제 경로 표시
- **저장 위치 설정:** Android에서 파일 관리자로 접근할 수 있는 수신 폴더 선택, 데스크톱에서 원래 파일명으로 열기 및 다른 이름으로 저장
- **신뢰한 기기와 재연결:** 첫 승인 시 기기의 장기 식별 정보를 기록하고, 다음 연결부터 동일한 기기인지 확인
- **전달 확인:** 상대 기기에 메시지가 성공적으로 저장되면 전달 완료로 표시
- **로컬 채팅 기록과 초안:** 클라우드 동기화 없이 기기 내부에 보관
- **5개 언어**, 라이트/다크 테마 및 글자 크기 설정
- **계정 없음, 텔레메트리 없음, 클라우드 채팅 API 없음**

## 💻 플랫폼별 지원 현황

| 플랫폼 | LAN | 클래식 블루투스 | 텍스트 | 이미지 / 파일 | 상태 |
| --- | --- | --- | --- | --- | --- |
| Android | ✓ | ✓ | ✓ | ✓ | 주요 모바일 클라이언트 |
| Windows GUI | ✓ | ✓ | ✓ | ✓ | 정식 버전 |
| Linux GUI | ✓ | ✓ | ✓ | ✓ | 정식 버전 |
| macOS / iPhone / iPad | ✓ | — | ✓ | ✓ | 네이티브 프리뷰, Android와 기능이 완전히 같지는 않음 |
| Terminal (Windows / Linux x64) | ✓ | — | ✓ | ✓ | TUI/CLI 프리뷰 |

데스크톱 클라이언트는 실행 환경을 포함한 패키지로 배포되므로 Java를 별도로 설치할 필요가 없습니다. Windows 및 Linux의 자세한 사용법과 검증 범위는 [Windows 안내](../windows.md)와 [Linux 안내](../linux.md)를 참고하세요.

iOS, iPadOS, macOS에는 Apple 시스템 구성 요소를 사용하는 **Swift / SwiftUI 네이티브 프리뷰**가 제공됩니다. NIM4 기반 LAN 암호화 텍스트 통신, 파일·이미지 전송, 기기 승인, 로컬 기록, QR 코드를 통한 기기 식별 정보 확인을 지원합니다. Mac 패키지는 Intel 및 Apple Silicon을 지원하며 iPhone/iPad는 동일한 기기용 IPA를 사용합니다. Apple의 프로필 이미지, 블루투스/P2P/독립 파일 전송 경로 등은 아직 완전히 구현되지 않았습니다. 실제 기기 및 성능 검증 현황은 [Apple 안내](../apple.md)와 [#31](https://github.com/GHOST-AKU/wozai/issues/31)을 확인하세요.

**Apple 프리뷰에는 정식 배포용 서명이 없습니다.** Mac 패키지는 임시 ad-hoc 서명만 적용되었으며 Developer ID 서명이나 공증은 없습니다. iPhone/iPad IPA는 서명되지 않아 다운로드한 파일을 누르는 것만으로 설치할 수 없고, 사용자가 직접 서명하여 사이드로딩해야 합니다. 최소 요구 버전은 macOS 14 및 iOS/iPadOS 17입니다. 무료 계정으로 서명을 갱신하는 과정까지 포함한 자세한 내용은 [설치 안내](../releases/native-preview-install.md)를 참고하세요.

## ⌨️ NearbyIM Terminal (프리뷰)

**NearbyIM Terminal**은 Rust로 별도 구현한 터미널 클라이언트로, 전체 화면 TUI와 CLI를 모두 제공합니다. 주요 실행 명령은 `nearbyim`(Windows에서는 `nearbyim.exe`)이며 실행 시 JRE, GUI, Android SDK가 필요하지 않습니다. [Windows/Linux x64 프리뷰 패키지 다운로드](https://github.com/GHOST-AKU/wozai/releases/tag/v0.3.3-preview.1) 후 압축을 풀고 `nearbyim`을 실행하거나, `nearbyim --help`로 명령을 확인하세요.

- NIM4 기기 승인 및 안전 코드, LAN 기기 검색·주소 직접 연결, 텍스트, 기록·초안, 스트리밍 파일 전송, 대기열, 일시 정지·이어받기·저장 확인 응답을 지원합니다. 프로필 이미지 동기화와 QR 확인도 지원합니다.
- **기본적으로 LAN 수신 대기는 꺼져 있습니다.** 알 수 없는 기기나 수신 파일을 자동 승인하지 않습니다. TUI 첫 실행 시 설정을 안내하며, CLI는 JSON 출력과 종료 코드를 제공합니다. 자세한 내용은 [Terminal 사용 안내(영어)](../../terminal/README.md)를 참고하세요.
- 공개된 `0.3.3-preview.1`에 포함된 Terminal의 내부 버전은 `0.1.0-dev`입니다. 이후 새 빌드에는 공통 버전 `0.3.3-preview.2`를 사용합니다. Windows 패키지에는 Authenticode 서명이 없으며, 현재 프리릴리스에는 macOS Terminal 실행 파일이 포함되지 않습니다.
- 블루투스/P2P 어댑터와 전체 검증은 여전히 개발 중입니다. 터미널·IME·SSH/tmux·실제 기기 간 상호 운용성 및 성능의 검증 범위는 [#38](https://github.com/GHOST-AKU/wozai/issues/38)에 정리되어 있습니다. 기존 GUI를 대체하지 않으며, 0.3.2 정식 버전의 배포 파일은 그대로 유지됩니다.

## 📡 채팅 시작하기

다음 UI 조작 방법은 Android / Windows / Linux GUI 정식 버전을 기준으로 합니다. Apple 설치 및 연결 방법은 [프리뷰 안내](../releases/native-preview-install.md), Terminal 조작 방법은 [Terminal 사용 안내(영어)](../../terminal/README.md)를 참고하세요.

### LAN

1. 두 기기를 같은 Wi-Fi에 연결하거나 한 기기에서 핫스팟을 켭니다.
2. 양쪽에서 「我在」를 열고 **근처 → LAN → LAN 수신 시작**을 선택합니다.
3. 한쪽에서 다른 기기를 검색하고 채팅을 시작합니다.
4. 첫 연결에서는 수신 측에서 해당 기기를 신뢰할지 결정합니다.
5. 이후에는 채팅 기록에서 바로 재연결을 시도할 수 있습니다.

자동 검색이 실패하면 상대 기기의 **내 연결 주소**에 표시된 IP 주소와 포트로 직접 연결할 수 있습니다. 게스트 Wi-Fi, 학교 네트워크, VPN 또는 클라이언트 격리 설정이 기기 간 통신을 막을 수 있습니다.

### 블루투스

1. 두 기기에서 블루투스를 켜고 「我在」의 **근처 → 블루투스 → 수신 시작**을 선택합니다.
2. 연결을 받을 기기에서 일시적으로 다른 기기가 검색할 수 있도록 허용합니다.
3. 다른 기기가 상대를 검색해 채팅을 시작하고, 처음 사용할 때는 시스템 안내에 따라 페어링합니다.
4. 첫 승인 후에는 「我在」가 기기 식별 정보를 기억하므로 채팅 기록에서 다시 연결할 수 있습니다.

## 🔐 보안과 개인정보 보호

0.3.2는 **Noise XX / X25519 / 운영체제 제공 AES-256-GCM / SHA-256**으로 기기 간 텍스트와 첨부 파일을 보호합니다. 기존 P-256 기기 루트 신원 서명은 양쪽 기기의 신원, Noise 공개 키, 핸드셰이크 기록 및 지원 기능을 서로 연결합니다. 기존 기기 UUID와 신뢰 기록은 유지됩니다. 연결할 때마다 새 세션을 수립하며, 인증·무결성 또는 버전 검증에 실패하면 연결을 종료합니다.

주의 사항:

- **이미 배포된 0.3.1의 LAN 통신 내용은 여전히 평문입니다.** 이 버전의 NIM3에는 인증과 서명이 있지만 종단간 암호화는 없으며, 블루투스에는 별도로 운영체제의 RFCOMM 링크 보호가 적용됩니다.
- 닉네임은 실제 신원 인증을 의미하지 않습니다. 최초 승인(TOFU)은 기기의 공개 키를 받아들이는 것이므로 대면하거나 신뢰할 수 있는 경로를 통해 상대의 신원을 확인해야 합니다.
- 채팅 기록과 첨부 파일은 기기에 **암호화되지 않은 상태로 저장**됩니다. 전송 암호화가 디스크 암호화를 의미하지는 않습니다. 앱은 시스템 자동 백업을 비활성화합니다.
- 채팅 기록을 삭제해도 해당 기기에 대한 신뢰가 자동 해제되지는 않습니다. 기기 정보나 설정에서 별도로 신뢰를 해제할 수 있습니다.

구현에는 표준 테스트 벡터, 서로 다른 구현 간 상호 운용성 테스트, 실패 사례 테스트가 포함되어 있지만, 정식 암호학적 보안 감사나 실제 블루투스 기기 검증은 아직 완료되지 않았습니다.

## 🧩 NIM 프로토콜과 버전

NIM은 「我在 / NearbyIM」가 기기 사이에서 메시지와 첨부 파일을 교환하는 애플리케이션 계층 프로토콜의 이름입니다. 메시지 형식, 인증, 전달 확인, 파일 전송 규칙을 정의합니다. LAN, 블루투스, Wi-Fi Direct는 **전송 경로**이며 서로 다른 NIM 버전이 아닙니다. 프로토콜 버전은 앱 버전 번호와도 다릅니다.

| 프로토콜 | 사용 시기 | 주요 기능과 보안 경계 |
| --- | --- | --- |
| NIM1 | 초기 프로토타입 | 기본 메시지 프레이밍. 이후 버전의 기기 신원 서명 및 종단간 암호화는 없음 |
| NIM2 | 0.2.0부터의 초기 버전 | P-256 기기 신원, 챌린지 핸드셰이크, 프레임별 서명 및 재생 공격 방지. 내용은 여전히 평문. [과거 형식 안내](../protocol-v2.md) |
| NIM3 | 0.3.1 정식 버전 | 바이너리 첨부 파일 청크, 흐름 제어, SHA-256 검증 및 저장 확인 응답. 신원 서명만으로 내용이 암호화되지는 않음 |
| **NIM4** | **0.3.2 정식 버전** | **Noise 종단간 암호화**, 장기 기기 루트 신원 유지, 안전 코드 확인, 대용량 파일 스트리밍 및 영구적인 이어받기 |

현재 Android, Windows, Linux 클라이언트는 모두 **NIM4**를 사용하며 NIM3 또는 평문으로 자동 다운그레이드하지 않습니다. 0.3.2와 0.3.1은 직접 통신할 수 없으므로 양쪽 모두 업데이트해야 합니다. 서로 다른 NIM4 빌드 사이에도 지원 기능 확인이 필요합니다. 프로토콜을 업데이트해도 기존 채팅 기록과 기기 루트 신원은 유지되지만, 이전 버전 클라이언트와 계속 연결할 수 있다는 뜻은 아닙니다.

현재 텍스트, 이미지, 파일을 지원합니다. 그룹 채팅, 음성, 인터넷 중계, 메시지 자동 재전송은 아직 포함되지 않습니다.

## 🛠️ 소스 코드에서 빌드하기

### Android

JDK 17, Python 3, Android SDK Platform 36, Build Tools 35.0.0 및 AGP 8.13을 지원하는 Android Studio가 필요합니다.

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

Windows PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
```

디버그 APK 출력 경로:

```text
app/build/outputs/apk/debug/app-debug.apk
```

최소 지원 버전은 Android 8.0 / API 26이며, targetSdk는 36입니다.

### 핵심 기능 검증

Android SDK 없이도 일부 프로토콜, 기기 신뢰 및 리소스 검증을 실행할 수 있습니다.

```sh
sh tools/test-i18n.sh
sh tools/test-core.sh
sh tools/test-trust.sh
sh tools/check-source.sh
```

Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test-i18n.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test-core.ps1
```

이 검증은 Android 전체 빌드나 실제 기기 검수를 대신하지 않습니다. 전체 과정은 [기기 테스트 안내](../device-test.md)를 확인하세요.
