# 文件与照片传输设计

日期：2026-10-04。分支：`feat/file-photo-transfer`。基线：最新 main `1a322c8`，包含已合并的 PR #10。

2026-10-04 用户真机反馈后的 Android 交互调整：已同意且完成认证的聊天会话内自动接收附件，不再逐附件要求确认；仍执行大小、空间、摘要、单接收任务和持久化回执检查，并可取消。Windows/Linux 暂保留逐附件接收操作。以下初版关于 Android 独立附件确认的描述由这一明确用户要求替代。

Android 输入栏参考 WhatsApp 的圆角输入框、框内表情／附件入口和独立圆形发送按钮；图标使用 Google 官方 Material Icons。照片采用可点击预览气泡，打开内部离线查看器，支持缩放和保存；普通文件以文件名、易读大小及状态显示，点击打开，长按另存为。收起附件入口时不显示容量／未加密说明，该说明保留在展开的附件面板。Android 保留已送达照片的私有副本供发送方预览，恢复历史时保留、清空聊天时删除；没有发送回执的暂存照片仍清理。预览缓存限 12 张，每张解码最长边 512px；内部查看器最长边 2048px，原图内容不改写，按 EXIF 方向显示。

## 目标与范围

用户要求先完成文件／照片传输，再完成加密。本轮在 Android、Windows、Linux 的已认可一对一会话中支持局域网和经典蓝牙附件互传。保留现有设备 UUID、长期 P-256 签名密钥、信任和文字历史。

附件内容本轮没有应用层加密。继续使用设备签名证明身份和校验帧完整性；蓝牙链路安全由系统提供，不能称为端到端加密。更新路线图、协议说明和帮助文案，如实说明这一顺序和范围。

成功标准是用户能选择文件或照片、发送，对方能接受或拒绝，双方看见进度并能取消；收到的完整附件经校验和保存后可打开或另存为。照片默认保留原始字节，不压缩、不删除 EXIF。格式支持的图片显示缩略图，其他图片格式仍可作为附件打开。

本轮每次选择一个附件，单附件上限 1 GiB；每个会话最多同时一个发送和一个接收，包括待接受的附件。支持零字节文件。保留现有单活动会话，不扩展 Issue #6，不处理暂停中的 Windows 发现问题。断线不自动重发、不实现断点续传、目录传输、相机拍摄、群聊或多文件批量发送。

## 方案选择

推荐在现有聊天连接内使用二进制分块附件帧：两种传输共用协议与状态机，文件数据走同一已认可连接；新增附件帧有严格长度限制，不使用文本或 Base64 承载文件。

独立文件连接会额外涉及 TCP 端口、蓝牙服务与连接生命周期，不能自然复用当前认可流程。把附件编码为文字消息会污染历史并增加复制和内存开销。这两种方式均不采用。

## 协议与兼容

附件属于线协议扩展，采用新的签名协议版本 NIM3；此名称表示协议版本，不表示加密已实现。双方需要升级，新版不自动降级到旧协议。识别旧 NIM2／其他不支持的版本时，新客户端显示明确的升级提示；旧客户端的错误提示取决于旧实现。升级不替换设备身份或信任。

保留原来的双 OFFER、双 PROOF、带方向绑定和递增序列的签名 RECORD 结构。OFFER 增加固定版本的能力字段：文字、附件 v1、最大块大小和最大附件大小。能力字段与完整双方 OFFER 一起进入签名证明，发现广播只是路由提示。未知可选能力可以忽略，必须支持文字；附件只有在双方宣布附件 v1 能力且双方 READY 后才可用。附件边界取双方能力与本地硬上限的较小值，远端值不得扩大本地内存或文件限制。

新增帧：

- `FILE_OFFER`：附件 UUID、发送时间、显示名称、MIME 提示、总字节数和 SHA-256。
- `FILE_ACCEPT`／`FILE_REJECT`：附件 UUID；拒绝附有固定枚举原因。
- `FILE_CHUNK`：附件 UUID、字节偏移、非空原始字节块。单块最多 32 KiB。
- `FILE_PROGRESS`：附件 UUID、接收端已写入的累计字节数，作为流控反馈，不代表完整保存。
- `FILE_FINISH`：附件 UUID；接收端检查实际字节数和最终 SHA-256。
- `FILE_RECEIPT`：附件 UUID；完整文件与聊天元数据持久化成功后发送。
- `FILE_CANCEL`：附件 UUID和固定枚举原因；双方都可发出。

所有帧有各自的字段和长度边界，在分配前校验外层长度。名称最多 255 个 Unicode 码点且不超过 1024 个 UTF-8 字节；MIME 最多 127 个 ASCII 字节；摘要固定 32 字节。总长度、偏移、进度采用非负 int64，并检查加法溢出。禁止未认可接收、未知附件的数据块、越界、重叠、重复或乱序块、超出声明大小、无效 UTF-8、意外字段和错误签名。无效线协议关闭连接并清理正在传输的附件；用户拒绝、源读取失败或磁盘不足只结束对应附件。

保留文字帧、文字保存回执和心跳规则。签名记录最大长度按 32 KiB 附件块及固定字段开销计算，不能把整份文件作为一个 RECORD。

## 传输状态与资源

新增独立、平台无关的 `AttachmentTransfer` 状态机，通过有界输入源、接收存储接口、帧发送接口和事件监听器连接控制器。文件 I/O、摘要和缩略图解码都不在 Android 主线程或 Swing EDT 上运行。

发送顺序：选择 → 准备 → 待接受 → 传输中 → 待保存回执 → 已送达。拒绝、取消和明确错误分别进入终态；发送 FINISH 后断线而未收到回执，显示结果未知，对方可能已经保存。只有 FILE_RECEIPT 可以使发送端显示已送达。

接收顺序：待接受 → 传输中 → 校验／保存中 → 已接收。明确同意附件与认可聊天是独立操作，信任设备不等于自动接受附件。拒绝前不创建附件内容文件。

发送端先用固定缓冲区将选中的源复制到应用管理的暂存文件，计算实际大小与 SHA-256；这样兼容大小未知的 Android 内容 URI，并保证发送内容与 OFFER 一致。准备阶段也能取消，到达硬上限、权限失效或源读取失败立即终止。暂存文件在结束或退出后删除，发送记录不依赖原始路径持续可用。

单方向最多四个未获写入反馈的块；接收端使用有界串行工作队列。FILE_PROGRESS 的含义是此前数据已写入接收临时文件，释放发送窗口；进度只增不减，不能超过已发送长度。发送数据以块为单位排队，心跳、文字与取消有调度机会，不一次性填满现有 64 项写队列。界面进度更新合并到最多每 250 ms 一次，状态变更立即通知。

待接受超时 120 秒；传输阶段 60 秒无附件推进则终止该附件，不以持续心跳冒充传输进展。已有连接心跳超时继续生效。会话关闭、撤销信任、进程退出使该会话未完成附件终止；迟到帧或回调不能跨会话代次恢复旧任务。取消后停止产生块，接收端仅容忍该任务取消竞态中最多四个在途块并丢弃，超出即协议错误；结束任务的会话内标识保留在最多 16 项的有界表中，其他未知附件的数据块仍按协议错误处理。

重启后不恢复传输。正在准备、待接受、传输和校验中的记录恢复为中断；待保存回执的发送记录恢复为结果未知。启动清理暂存／部分文件以及无对应完成记录的孤立内容文件；清理范围限定在应用管理的附件目录。

## 存储和保存回执

接收内容放在应用管理目录，使用本地 UUID 派生的文件名；远端名称只作显示和导出建议，不用于构造本地路径。应用管理路径禁止符号链接或特殊文件，临时文件独占创建，沿用平台私有访问权限。过滤显示中的控制字符；导出建议排除路径分隔符、保留设备名和特殊路径名，不能覆盖既有文件而不询问。MIME 和后缀均是提示，不能据此自动执行或自动打开。

收到接受操作后检查可用空间，写同目录临时文件，并增量计算 SHA-256。只在 FINISH 后精确匹配声明大小和摘要时提交：同步文件内容 → 原子重命名 → 持久化完成聊天元数据 → FILE_RECEIPT。临时文件不提供打开入口。不支持原子提交或发生存储错误时不回执。

文件与数据库／属性文件不具有跨介质事务：先提交内容、再保存元数据；保存元数据失败不发送回执，删除孤立内容，删除失败留给启动清理。崩溃留下孤立内容也由启动清理处理。完成元数据存在但内容随后被外部删除，显示文件不可用，保留历史状态，不悄悄改成传输失败。

Android 为 SQLite 增加附件字段／表和显式版本迁移，保持旧文字记录、信任与顺序；桌面原子属性记录增加可选附件字段，缺少字段的旧记录仍按文字读取。键仍包含 peer UUID、消息 UUID、方向；同 UUID 的文字与附件不能互相覆盖。附件状态、名称、MIME、大小、摘要和应用管理的内容标识持久化，进度不逐块落库。

清空聊天先取消该会话的附件任务，再删除对应应用管理内容和附件元数据；不删除用户另存的副本，不撤销信任。拒绝、取消、校验失败和断线都删除未完成内容。

## 三端界面

输入区增加“文件”和“照片”入口，仅在当前选中会话已认可且支持附件时可用；发送文字不受正在传输影响。选择器返回时重新校验原会话和代次，不能因用户切换会话而发给另一个人。

Android 使用系统文档选择器，照片限制到图片类型；不请求全盘存储或完整相册权限。通过 ContentResolver 读取；打开已接收内容使用受限 FileProvider 和临时读授权；另存为使用系统创建文档选择器。导出失败不改变已经接收的状态。

Windows／Linux 使用系统文件选择流程。附件消息卡片显示名称、格式化大小、状态和进度，并按状态提供接受、拒绝、取消、打开和另存为。打开必须由用户点击，桌面通过平台默认处理程序打开。图片解码先读取尺寸并采样，有像素、输出尺寸和缓存上限，禁止按原图尺寸常驻内存；不支持或损坏的图片退回普通附件卡片。

统一更新现有五种语言目录、生成资源和消息摘要。保持字体缩放、主题与语言切换；按钮有读屏名称，进度有可读状态，桌面键盘可操作，消息更新保留用户滚动位置。缩略图工作结果必须与当前附件和界面代次匹配。

## 验收证据

1. 核心：真实流连接的双向文字与文件、零字节、跨块文件、SHA-256、大小和边界拒绝；身份替换、签名篡改、跨会话重放与旧版本拒绝。文字回执语义保持不变。
2. 状态机：接受前不得发送数据、拒绝、双向取消、重复／乱序／截断／过长块、超时、存储失败、断线和回执丢失；终态与迟到回调不串会话，临时资源全部释放。
3. 存储：Android 旧数据库迁移、桌面旧属性记录读取、同 ID 不同方向、文字／附件冲突、进程恢复与孤立内容清理、清空历史、导出副本保留。
4. 平台：Android 文档 URI、大小未知、权限失效、FileProvider、创建文档；桌面选择、打开／另存为、图片解码上限、键盘、大字体、多语言和实际打包运行时。
5. 性能：小堆限制下传送大于堆大小的生成文件，证明不会整文件入堆；记录缓冲区／队列边界、文字与取消响应、传输结束后的资源释放。Idle／Connected 与 Active 按性能文档建立同环境对照，区分堆与 RSS，不把短测称为无泄漏证据。
6. 三端构建与 CI：Android API 26／34 检查、Windows／Linux 核心、存储与 GUI／打包检查。真实设备双向 LAN 与蓝牙验证记录设备、系统、版本、大小、摘要、耗时和取消结果。

工作进展与验收证据写入附件功能 Issue，不另建 TODO 文件。缺少蓝牙真机继续在 #7 记录阻碍；缺少原签名密钥继续在 #8 记录升级阻碍。不以模拟链路代表蓝牙射频验收，不以调试 APK 构建代表保留数据升级通过；对应验收未完成时保持 Issue 开放。

## 后续加密边界

协议编码、签名封装、附件状态机和文件存储分别独立。下一轮单独设计经过身份签名认证的会话密钥协商与加密记录，再确定兼容策略和验收；本轮不预先添加未经设计的密钥字段或占位加密实现。
