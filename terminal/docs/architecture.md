# Implementation boundaries

`wire.rs` implements bounded NIM4 record and attachment-v2 codecs. `crypto.rs` performs Snow Noise XX, canonical P-256 SPKI root validation and transcript/role-bound ECDSA proofs. NIM4 authenticates its ten-byte envelope, which Snow's high-level transport API cannot pass as AAD. Only after a completed XX handshake, the split keys feed RustCrypto AES-256-GCM with the Noise AES-GCM big-endian nonce convention. Proof and subsequent records share each direction's counter. Bounds precede allocation; authentication/type/version errors close the stream; there is no fallback.

`profile.rs` owns the exclusive Terminal profile lock, persistent signing identity, SQLite FULL/WAL commits, pinned roots, manual verification, messages and drafts. `config.rs` holds explicit versioned preferences. No GUI data migration or shared identity is performed. Linux permissions and Windows DPAPI protect identity material; history is not an encrypted database. A newer database schema, missing established identity or corrupted identity stops startup.

`network.rs` owns each foreground session, consent/READY gating, serialized writes, a bounded record-reader channel, heartbeat/deadlines, unconfirmed text and file permission. Only one authenticated session may hold the runtime lease; handshake work has a separate finite cap. Closing the runtime shuts its sockets, requests stop and waits for worker cleanup/checkpointing; no background service is created. TUI/CLI consume the same commands/events. Same-profile CLI/TUI concurrency is rejected by the lock; there is no IPC.

`files.rs` owns bounded source reads, per-block/whole-file hashes, byte credit, identity/source/connection generation checks and checkpoints. Forced content precedes the committed receive offset. Resume re-hashes the committed prefix before exposing a new RESUME offset. Final no-replace publication precedes the saved checkpoint and COMPLETE receipt. A lost receipt is recovered through STATUS and re-verification of the saved file. Cancellation is a persisted tombstone, manual pause is distinct from connection loss, and receiver filenames never determine an arbitrary path. Sender sources must retain size/metadata and match the receiver's prefix. Sparse or very large files use the same streaming path, not whole-file buffering.

`discovery.rs` treats DNS-SD as routing hints. Advertisement requires explicit listening; active search is user initiated and bounded. It currently browses IPv4 results; direct IPv6 LAN addresses can be supplied. No native Bluetooth RFCOMM or Wi-Fi Direct backend is claimed.

`ui.rs` draws terminal cells, keeps grapheme-aware input and delegates operations. It filters untrusted control/Bidi content, uses an actual terminal cursor for IME positioning, bracketed paste and a drop guard/panic hook for terminal restoration. Frames are redrawn on changes. Terminal width determines layout; insufficient geometry produces a safe prompt. IME, SSH/tmux and Windows host behavior still require platform testing.

CLI JSON is a single final result, not a stream of interleaved progress objects. Operational output and diagnostic output are separated. Timeout uses monotonic clocks; presentation timestamps use UTC ISO 8601. `status` describes this profile/capabilities and reports `not_running`, because no daemon/IPC is queried.

The Java fixture deliberately imports the production Java channel, record codec and file engine, rather than reimplementing a convenient peer. Both roles exchange real encrypted TCP records. Unit fault injection and PTY automation complement those tests; they do not substitute for the design manual's Android/Windows/Linux device and terminal acceptance matrix. Source changes, evidence and remaining acceptance are tracked in Issue #38 and PR #41.
