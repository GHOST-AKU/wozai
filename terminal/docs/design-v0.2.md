## 0. 设计摘要与原则

**定位**：NearbyIM Terminal 是 NearbyIM 生态中的新客户端，而非现有 Swing GUI 的主题、窗口模式或换皮。它有独立的可执行程序、构建/发行资产、配置/身份与本地数据；复用 NIM4 网络协议与跨端互通测试标准，不要求依附原桌面 Java 运行时。

**核心体验**：键盘优先、视觉克制而精致，安全语义透明；终端中真实进行点对点文字、文件通信，能够在 Windows Terminal、Linux 常用终端、tmux、SSH 中使用。无账号、无遥测、无云端聊天服务器。

**统一入口**：`nearbyim` 打开 TUI；`nearbyim <subcommand>` 执行 CLI。TUI 和 CLI 共享应用核心但不同输出交互层；可选 `wozai` 仅是别名，不得有另一套数据或身份。

**技术候选**：先验证 Rust + Ratatui/Crossterm + Clap；备选 Go + Bubble Tea/Lip Gloss。以 NIM4 生产端真实互通、Unicode/IME、可执行体积、冷启动、内存、平台可用性与工程成本决定，不因视觉示例直接锁栈。

**协议事实（仓库 v0.3.2）**：
- NIM4 使用 Noise XX/X25519/AES-256-GCM/SHA-256、P-256 长期根身份证明；已发布客户端不自动降级到 NIM3 或明文。
- 文本帧上限为 **8192 UTF-8 字节**（并非 8192 字符）；普通消息不为空。
- 单文件上限 **10 GiB = 10,737,418,240 字节**；拥有检查点、校验、保存回执。
- `已保存/已送达` 表示对端持久保存，不等同 `已读`；未确认消息不应自动声称成功或擅自重发。
- LAN mDNS / IP:port 为首要路径；蓝牙 RFCOMM 需独立平台验收。Linux GUI 历史文档说明当前桌面实现一次仅支持一位活动聊天对象，故终端首版优先采用单活动连接并透明呈现、完整保留多个历史会话；未来多并发为独立能力验收项。

## 1. 信息架构与界面

### 1.1 主导航

- **Chats**：历史会话、对端昵称、最近消息摘要、待确认/失败数量、连接状态。
- **Nearby**：LAN 发现结果和手动 IP:port 连接；按明确用户动作开启搜索、取消和重试。
- **Transfers**：文件发送/接收、进度、校验、保存位置、暂停/续传/取消、失败原因。
- **Security**：可信设备、仅本次认可、安全码人工核验、身份变更警报、撤销信任。
- **Settings**：个人昵称、接收目录、语言、主题、颜色能力、终端兼容性、监听设置与日志诊断。
- **Help**：快捷键、命令说明、错误定位与版本信息。

信息架构不是要求屏幕常驻六个导航栏：常用功能以会话、附近和文件为主，其他放命令面板 `Ctrl+K` 或 `?` 帮助。

### 1.2 页面布局

- **宽屏 ≥110 列**：会话列表（建议宽 24–30）+ 消息流（剩余）+ 可折叠设备详情（宽 24–28）。
- **中等 72–109 列**：会话与消息双栏；设备详情通过侧弹层打开。
- **紧凑 45–71 列**：单栏导航，Enter 进入会话，Esc 返回会话列表。
- **极窄 <45 列**：只显示最小文本导航/报错；无法保留有效编辑区域时明确提示终端需增宽。
- **高度不足**：高度低于 16 行时显示简化提示，避免越界绘制；恢复后自动重建布局。

### 1.3 风格与视觉 Token

**风格名称**：Quiet Terminal。默认午夜深色；不依赖 emoji 装饰，不强行复制 Android/GUI Material Design。两级字体强调只能靠字形/粗细/间距实现，不能假设可设任意字体或字号。

| Token | Midnight 默认 | Paper | Sage |
|---|---|---|---|
| 背景 | `#111A17` | `#F4F2EC` | `#183025` |
| 主要前景 | `#E2EBE3` | `#26372E` | `#E1F1E2` |
| 次要前景 | `#92AB98` | `#64786D` | `#ABC5A8` |
| 强调色 | `#9CD1A9` | `#3F6053` | `#C1DDAC` |
| 高亮背景 | `#274435` | `#E5E8E0` | `#31503B` |

还需 **Mono** 无色主题，遵守 `NO_COLOR`、`TERM=dumb`、`--no-color`；在 256 色、16 色和无框线终端回退。错误、信任、已保存、已核验状态一律图标加短文字，不可只看颜色区分。

**排版**：避免每条消息都画重边框；区分“对方”和“我”的对齐/小标签；时间戳不抢视觉；传输块用文件名、数值、进度条、状态字而不是占一屏的表格；终端无法可靠渲染图像时显示文件名/类型/大小/打开保存位置，而非宣称支持通用图片预览。

### 1.5 必须设计的特殊状态

1. **首次启动**：昵称、独立设备身份创建说明、接收目录、是否开启 LAN 监听。无账号/无云，不静默开放监听。
2. **空状态**：暂无历史会话，突出“搜索附近设备 / 输入地址”；离线不制造虚假的在线联系人。
3. **发现中**：显示进度、倒计时、取消、网络/组播限制与“手动输入地址”。
4. **首次来访**：独立安全模态，显示来源/设备指纹摘要和“仅本次 / 记住 / 拒绝”；明确这是 TOFU 而非人工核验。
5. **人工核验**：单独打开安全码，比对后显式标为已核验；改变根密钥必须阻断并解释。
6. **连接中/断连**：明确尝试中、已连接、重连失败；不可因历史记录或可发现而标为在线。
7. **消息状态**：编辑中、正在发送、未确认、对端已保存、失败。不能显示不存在的“已读”。
8. **文件**：等待、传输中、手动暂停、恢复中、校验中、已保存、失败；显示已传字节/总量/瞬时和平均速度/估算剩余时间（仅当有足够样本）。
9. **终端异常**：窗口缩放、SSH 断线、Ctrl+C、异常退出应恢复光标、颜色与终端原始模式。
10. **隐私**：昵称、正文、文件名等不可信字符串禁止直接作为控制序列写入终端；ANSI/OSC、控制字符、Bidi 混淆均要过滤或安全可视化。

## 2. 交互与完整用户流程

### 2.1 首次打开

`nearbyim` → 检测 TTY 与终端能力 → 若无独立数据目录，则提示“为终端客户端新建独立身份” → 昵称（满足现有 NIM4 格式）→ 默认保存目录 → 监听选项（默认不主动启用）→ 进入空会话屏。创建失败不得生成一套无提示的新身份或忽略权限错误。

### 2.2 发现、连接、信任

`Nearby` → LAN 扫描（明确有界/可取消）→ 选设备 → 连接 / Noise 握手 → 用户认可（仅本次/记住/拒绝）→ 会话 READY → 页面分别标识“已加密”“身份未核验”。人工比对安全码后才显示“已核验”。设备 UUID/昵称/IP/mDNS 不是身份校验凭据。只有受信任密钥确实匹配才能自动重新建立会话。

### 2.3 聊天

选择历史会话 → 显示本地记录与真正连接状态 → Enter 发文字 → 先显示“发送中” → 远端存储 ACK 后才显示“已保存”；断开/超时显示“未确认”，不自动标为成功也不偷偷重发。切换到其他设备若需要断开当前活动连接，先提示；进行中的文件任务应先选择继续等待或安全暂停。

### 2.4 文件

在会话按 `a` / 命令面板 Attach → 系统路径选择/手输路径（CLI 可指定）→ 显示大小、接收端、覆盖策略与确认 → 进行 NIM4 加密传输 → 进度/校验/保存回执 → 打开存放目录。默认绝不自动覆盖同名文件；路径必须规范化，拒绝目录穿越、恶意设备提供的绝对路径、symlink 逃逸；接收侧要允许配置是否自动接收已可信设备文件。中断后按检查点继续，但不保证未被真实测试的任何路径恢复。

### 2.5 多进程与退出

交互 TUI 拥有该 Profile 的独占锁。相同 Profile 的 CLI 命令若有活跃 TUI：
- 优先由**权限受限本机 IPC** 转交正在运行的客户端；如果暂不实现 IPC，则显示 `PROFILE_BUSY` 并拒绝并发写入，绝不打开第二个同库写进程。
- 没有 TUI 时，一次性 `send` 可以短暂初始化核心、连接可信对端、等待保存回执或超时并退出；不需要自动常驻 daemon。
- `nearbyim listen` 可显式以**前台**方式开启接收；Ctrl+C 停止。
- 退出 TUI 若正在传文件，提示“退出将暂停/中断任务”；必须保存可恢复检查点，不能假装后台继续传输。
- 使用 SSH 时，发现和网络连接发生在**运行 nearbyim 的远端机器**而非 SSH 操作者本机。

## 4. CLI 公共契约

### 4.1 命令树（期望接口）

```text
nearbyim
├─ [no args]                  Open interactive TUI
├─ chat <peer-id>             Open TUI focused on a peer
├─ peers
│  ├─ scan [--timeout 8s]    Bounded LAN peer discovery
│  └─ show <peer-id>          Discovery/trust metadata
├─ chats
│  ├─ list                   Local conversations
│  └─ show <peer-id>          Local message history
├─ send <peer-id> (--text X | --stdin | --file PATH)
├─ files
│  ├─ list                   Local transfer records
│  ├─ resume <transfer-id>   Resume supported checkpoint
│  └─ cancel <transfer-id>   Cancel specified task
├─ listen [--lan]            Foreground inbound listening
├─ identity
│  ├─ show                   Local identity summary; never private key
│  └─ verify <peer-id>       Interactive safety-code comparison
├─ trust
│  ├─ list
│  └─ revoke <peer-id>       Explicit confirmation; not --yes bypass
├─ status                    Local state, optional active-session IPC
├─ doctor [--json]           Redacted diagnostics
├─ config {list|get|set}
├─ completion {bash|zsh|powershell}
├─ --help / --version
└─ [global] --json --no-color --timeout --profile --verbose
```

CLI 的 `<peer-id>` 使用明确且稳定的本地联系人引用；可提供“昵称唯一时解析”，但重复昵称必须要求消歧，**绝不可仅凭未认证昵称进行敏感操作**。`--profile` 指向独立 Terminal Profile，不能随意指向现有 GUI 数据目录并复用其私钥。用户提供了具体地址时提供可解析的 `--address <host:port>` 参数，但首次信任仍必须互动确认。

**重要语义**：
- `nearbyim chat <peer>` 才是进入一个持续交互会话；不要把瞬时 `connect` 命令解释为“退出后仍保持持久连接”。如保留 `connect`，明确它等价于 `chat` 而非开启隐形后台服务。
- `nearbyim send` **必须等到远端已保存回执**才能以状态 `saved` 成功结束；没有收到回执则返回 `unconfirmed` 和非零码，即使本地套接字写入成功。
- CLI 文字发送禁止与文件参数同时使用；大于 NIM4 8192 UTF-8 字节时提前拒绝并显示“字节数”，不能按 UTF-16 单元截断。
- `--stdin` 支持管道输入；非 TTY 默认不打开 TUI，也不隐式进行信任确认。
- 默认 CLI 扫描耗时有界，支持 `--timeout`；无法发现 mDNS 时仍支持显式地址路径。
- 非交互传输允许非危险的标准 `--yes` 用于普通本地确认，但**不能跳过未知身份首次认可、密钥变化或安全码人工比对**。

### 4.2 输出与错误

- 人类输出：成功数据 → stdout，诊断/错误 → stderr；短、清楚、可复制。
- `--json`：单个稳定对象输出到 stdout，包含 `schema`、`ok`、`status`、标识符和可预测的错误对象；结构化结果避免交杂日志。
- 所有脚本输出禁止 TUI ANSI 控制序列；管道输出默认无颜色无动画，遵守 `NO_COLOR`。
- `status` 不可假称存在一个永久在线的后台连接。若无驻留进程或 IPC，返回 `not_running` 而非“设备离线”。
- 输出时间用明确的 ISO 8601 表示，内部使用单调时钟计算 timeout；路径按平台显示/转义。
- 输出中的昵称、消息、文件名需要防止 ANSI/OSC 终端注入；JSON 必须正确转义。

建议成功 JSON：

```json
{
  "schema": 1,
  "ok": true,
  "operation": "send_text",
  "peer_id": "example-peer-id",
  "message_id": "example-message-id",
  "status": "saved",
  "protocol": "NIM4"
}
```

未确认示例：

```json
{
  "schema": 1,
  "ok": false,
  "operation": "send_text",
  "message_id": "example-message-id",
  "status": "unconfirmed",
  "error": {"code": "ACK_TIMEOUT", "message": "No remote storage receipt before timeout"}
}
```

### 4.3 退出码规范（拟定，发布后不随意更改）

| 码 | 意义 |
|---:|---|
| 0 | 已完成；发送须已取得目标确认 |
| 2 | 参数、用法或输入校验错误 |
| 3 | 设备/会话/资源不存在或不可识别 |
| 4 | Profile 正在占用；资源冲突 |
| 5 | 网络/对端不可达 |
| 6 | 必须交互授权，当前不能继续 |
| 7 | 对端身份变化/签名不匹配 |
| 8 | 协议版本或加密握手失败 |
| 9 | 本地 I/O、存储、权限或空间失败 |
| 10 | 超时，结果未确认 |
| 11 | 用户主动取消 |

通过 `--json` 保留细粒度 `error.code`，退出码用于脚本快速分支，不需要每个异常一套 exit code。

## 5. 数据与安全模型

**身份**：首次启动自动生成 Terminal 专属 P-256 根身份和 Noise 所需凭据。作为一个新的逻辑设备，与 GUI 相互识别但不复制 GUI 私钥；拒绝同时写同一存储目录。允许用户在独立文件备份/迁移需求中理解安全边界，但本期不开放“继承 GUI 身份”的隐式功能。

**本地存储**：使用原生轻量 SQLite 或有明确定义的等价方案，明确存储版本和原子保存；Linux XDG 默认数据目录并用 0700/0600 等文件权限；Windows 使用当前用户 DPAPI 等 OS 保护手段。区分“传输已加密”与“磁盘数据未必加密”，不夸大本地保密能力。

**信任**：首次认可 TOFU、人工安全码核验、记住设备、仅本次、拒绝、撤销信任分离；UUID/昵称/IP/蓝牙配对都不等于密码学信任。根身份变化 fail closed。

**文件**：默认禁止覆盖、越界路径和不安全链接；不自动执行收到的文件；临时文件/检查点应在最终校验后原子保存，空余空间不足必须优雅失败。

**终端安全**：将对端控制字符、转义序列、终端标题控制、OSC 52 剪贴板写入、Bidi spoofing、异常宽字符视为不可信文本，安全显示或提示；不让富文本渲染器直接执行来自对端的 escape codes。

**日志**：默认不记录密钥、消息正文、安全码、令牌；诊断和 JSON 默认脱敏，只有显式用户授权的单次导出可补充有限网络元数据。

## 6. 性能预算（设计目标，尚未经实现验证）

以下为**待 Spike 冻结的候选发布门槛**，不代表已有实测，也不是对 Rust/Go 的自动保证。测试均采用可追溯 Release 优化构建、同配置电脑、已创建身份、无网络扫描的冷启动/空闲场景，平台分别计算 10 次/多轮中位数与 P95，并记录机器、OS、终端、源码提交与测量工具。

| 指标 | 建议发行门槛 | 理想目标 |
|---|---:|---:|
| CLI `--help` 冷启动 P95 | ≤ 500 ms | ≤ 150 ms |
| 空会话 TUI 冷启动 P95 | ≤ 1,000 ms | ≤ 400 ms |
| 交互 TUI 空闲 Linux RSS | ≤ 60 MiB | ≤ 30 MiB |
| 交互 TUI 空闲 Windows Working Set | ≤ 80 MiB | ≤ 40 MiB |
| 优化后的客户端分发包 | ≤ 25 MiB | ≤ 12 MiB |
| 空闲 CPU（单核占用） | < 1% | 接近 0% |
| 普通按键到更新的本地交互 P95 | ≤ 50 ms | ≤ 16 ms |

真实文件吞吐不可设一个与网卡/无线环境无关的绝对下限：与同网络、同文件、同方向的现有 v0.3.2 GUI 对照，量化应用层净吞吐/CPU/内存并定位显著退化；不允许把较差网络条件误判为软件问题。

- 蓝牙 RFCOMM 真机 Windows/Linux 互通及稳定性测试。未通过不得在该平台声称支持。

## 8. 必须保留的测试输入与可复现证据

- **语言**：中英混排、繁体、日文、韩文、 combining marks、家庭/肤色/职业 ZWJ Emoji、颜文字、极长 URL、右至左控制字符。
- **输入长度**：0B、8191B、8192B、8193B UTF-8 文本；文件名称有换行、ANSI、反斜杠/斜杠、`.` / `..`、保留设备名、超长 Unicode。
- **环境**：Windows Terminal PowerShell / Linux xterm/Kitty/GNOME Terminal 至少代表性组合；tmux + SSH；TrueColor/256/16/no-color、`TERM=dumb`、重定向 stdout。
- **网络**：同 LAN 发现、手动 IP、mDNS 被阻断、IPv4/IPv6 可达条件、端口占用、VPN/客户端隔离、接收方重启、文件中途断路、无法获得回执。
- **身份**：首次认可、仅本次、记住、撤销、替换根公钥、错误版本、Noise 握手失败、伪造回执。
- **存储**：目录不存在/不可写、迁移失败、磁盘空间不足、并发启动、崩溃重启、权限变化、恶意 symlink、备份/恢复说明。
- **证据**：每项记录客户端构建提交、设备/OS/终端、步骤、预期与实际、日志摘要、截图/文本帧、结果；自动模拟与实体设备证据分别标注。

## 9. 实施建议：设计冻结顺序，不人为削减新客户端定位

1. **规格冻结**：本文件、命令语法/退出码、状态机、身份/安全规则、CLI JSON schema、UI 宽度规则与视觉 token。
2. **技术 Spike**：Rust 与 Go 的最小终端渲染/IME/Unicode/跨端 NIM4 握手可行性，测体积/内存/CPU/启动，锁定技术路线与性能门槛。
3. **垂直整合**：独立身份 → 真实 NIM4 握手 → TUI/CLI 共享核心 → 文本与回执 → 文件与检查点 → CLI 自动化 → 跨平台包装。
4. **正式验收**：真实跨端回归、安全负向测试、终端环境矩阵、资源门槛及独立发行资产。旧 GUI 保持独立可用。

**特别说明**：工程上允许阶段性可运行版本作为测试里程碑，但不把一个缺少文件、安全或互通能力的“假 IM MVP”当作完成产品目标。

## 10. 还需要在实现前锁定的工程决策

- Rust/Go 栈、具体 NIM4 兼容库选择和 cross-language test harness。
- CLI `send` 与正在运行 TUI 的本地 IPC 是发布必须还是第一轮增强。
- Windows 密钥的 DPAPI 接入、Linux 秘密保护及磁盘数据是否默认加密（不能对尚未实现的 at-rest 加密做宣传）。
- 真实测试完成后的性能预算是否合理，以及机器基线和分发格式。
- 蓝牙 RFCOMM 首发平台范围，不能模糊地将 GUI 的支持自动算到新客户端头上。
